# 排班列表接口

基础路径：`/api/attendance/schedule/list`（S1~S9）、`/api/attendance/schedule/swap`（调班单查询/详情）

统一返回结构：`ReturnInfo<T>`

公共规则：
- Content-Type：`application/x-www-form-urlencoded`，参数通过表单提交
- tokenID 通过 query 参数传递，如 `?tokenID=xxx`
- 列表类型参数通过同名参数多次传递，如 `selectedTalentCodes=30028&selectedTalentCodes=60071`

---

## 1. S1 排班列表参数查询

`POST /api/attendance/schedule/list/params`

前端进入排班列表页面时调用，返回页面初始化所需参数（默认日期、组织范围、操作权限）。

### 请求参数

无请求参数。权限信息从登录上下文自动获取。

### 响应

```json
{
  "success": true,
  "data": {
    "defaultStartDate": "2026-04-29",
    "defaultEndDate": "2026-05-06",
    "orgScopes": [
      { "deptCode": "100", "deptName": "研发部" },
      { "deptCode": "200", "deptName": "财务部" }
    ],
    "canView": true,
    "canEdit": true,
    "canSwap": true,
    "canTimeRevision": true,
    "canExport": true,
    "readonlyReason": null
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| defaultStartDate | String | 默认开始日期，今天往前 7 天，格式 yyyy-MM-dd |
| defaultEndDate | String | 默认结束日期，今天，格式 yyyy-MM-dd |
| orgScopes | List\<OrgScope\> | 当前用户可选组织范围 |
| canView | Boolean | 是否可查看排班列表 |
| canEdit | Boolean | 是否可编辑单日排班 |
| canSwap | Boolean | 是否可调班 |
| canTimeRevision | Boolean | 是否可排班时间修订 |
| canExport | Boolean | 是否可导出 |
| readonlyReason | String | 只读原因，为 null 表示非只读 |

### 角色权限矩阵

| 角色 | canView | canEdit | canSwap | canTimeRevision | canExport | readonlyReason |
|------|---------|---------|---------|-----------------|-----------|----------------|
| 系统管理员 | true | false | false | false | true | "系统管理员仅允许查看排班" |
| HR | true | false | false | false | true | null |
| 考勤员 | true | true | true | true | true | null |
| 部门负责人 | true | false | false | false | true | null |
| 普通员工 | false | false | false | false | false | "当前用户无排班查看权限" |

### 业务规则

1. **默认日期**：固定为 today - 7 天 ~ today
2. **组织范围**：基于用户 `deptScopeItems` 构建，普通员工返回空列表
3. **纯内存计算**：不查询数据库，完全基于 `UserAuthContext` 计算
4. **权限判断**：
   - 普通员工（isEmployee=true 且非 admin/hr/clerk/leader）：所有操作禁止
   - 系统管理员：只读 + 导出
   - 考勤员：全部操作权限
   - 其他角色（HR、部门负责人）：查看 + 导出

## 2. S2 排班列表横向显示分页查询

`POST /api/attendance/schedule/list/horizontal/page`

按"员工 + 日期"粒度查询排班记录，一人一天一条。

### 请求参数

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| deptCode | 否 | String | 考勤组织编码，按组织过滤 |
| talentCode | 否 | String | 员工编码，精确匹配 |
| talentName | 否 | String | 员工姓名，模糊查询 |
| startDate | 是 | String | 开始日期，格式 yyyy-MM-dd |
| endDate | 是 | String | 结束日期，格式 yyyy-MM-dd |
| pageNo | 否 | Integer | 页码，默认 1 |
| pageSize | 否 | Integer | 每页条数，默认 20，最大 100 |

### 请求示例

```
Content-Type: application/x-www-form-urlencoded

deptCode=100&talentCode=30028&talentName=张&startDate=2026-05-01&endDate=2026-05-07&pageNo=1&pageSize=20
```

```json
    {

      "talentName": "张三",

      "attendanceOrgName": "研发部",
      "scheduleDate": "2026-05-07",
      "dateType": "workday",
      "shiftCode": "S001",
      "shiftName": "早班",
      "workStartTime": "09:00",
      "workEndTime": "18:00",
      "attendanceArchiveCode": "AT2026001",
      "attendancePolicyCode": "P001",
      "attendancePolicyName": "标准考勤制度",
      "fetchCardRuleCode": "FC001",
      "fetchCardRuleName": "标准取卡规则",
      "sourceType": "排班向导"
    }
  ],
  "total": 15,
  "currPage": 1,
  "message": "ok",
  "messageType": 0
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| scheduleDayId | Long | 日排班 ID |
| talentCode | String | 员工编码 |
| talentName | String | 员工姓名 |
| attendanceOrgCode | String | 考勤组织编码 |
| attendanceOrgName | String | 考勤组织名称，缺失时返回空字符串 |
| scheduleDate | String | 考勤日期，格式 yyyy-MM-dd |
| dateType | String | 日期类型（workday/restday/holiday） |
| shiftCode | String | 班次编码 |
| shiftName | String | 班次名称，缺失时返回空字符串 |
| workStartTime | String | 上班时间（取第一段明细） |
| workEndTime | String | 下班时间（取第一段明细） |
| attendanceArchiveCode | String | 考勤编号 |
| attendancePolicyCode | String | 考勤制度编码 |
| attendancePolicyName | String | 考勤制度名称，缺失时返回空字符串 |
| fetchCardRuleCode | String | 取卡规则编码 |
| fetchCardRuleName | String | 取卡规则名称，缺失时返回空字符串 |
| sourceType | String | 排班来源 |

### 权限规则

1. Controller 方法加 `@ScopeAuthRequired`
2. 普通员工返回空分页
3. 系统管理员可查全部排班
4. HR/考勤员/部门负责人按 `deptScopes` 权限范围查询
5. `deptCode` 不为空时必须落在用户权限范围内，越权返回空分页

### 查询规则

1. 只查 `is_deleted=0` 且 `status=1` 的排班记录
2. 通过 `attendance_archive` JOIN 确保只返回已建档员工
3. 日期范围：`schedule_date BETWEEN startDate AND endDate`
4. 日期范围最大 366 天
5. 排序：`schedule_date DESC, talent_code ASC`

### 参数校验

1. `startDate`、`endDate` 必填
2. `endDate` 不能小于 `startDate`
3. 日期范围最大 366 天
4. `pageNo` 默认 1，`pageSize` 默认 20、最大 100

### 数据补充

- 员工姓名：通过 IPS `talent_person` 补充
- 组织名称：通过 IPS `talent_organization` 补充
- 班次名称/上下班时间：通过 `attendance_shift_dict` + `attendance_shift_detail` 补充
- 考勤制度名称：通过 `attendance_policy` 补充
- 取卡规则名称：通过 `attendance_fetch_card_rule` 补充

## 3. S3 排班列表纵向显示分页查询

`POST /api/attendance/schedule/list/vertical/page`

按"员工"粒度分页，一人一条，日期范围内每天的班次名称作为动态日期列返回。返回结构为扁平 `LinkedHashMap`，日期列形如 `2026-05-01(五)`。

### 请求参数

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| deptCode | 否 | String | 部门编码。不传时查当前用户权限范围内所有员工 |
| startDate | 是 | String | 开始日期，格式 yyyy-MM-dd |
| endDate | 是 | String | 结束日期，格式 yyyy-MM-dd |
| pageNo | 否 | Integer | 页码，默认 1 |
| pageSize | 否 | Integer | 每页条数，默认 20，最大 200 |

### 请求示例

```
Content-Type: application/x-www-form-urlencoded

deptCode=102&startDate=2026-05-01&endDate=2026-05-04&pageNo=1&pageSize=20
```

### 响应

```json
{
  "success": true,
  "data": [
    {
      "talentCode": "30028",
      "talentName": "潘跃文",
      "attendanceOrgCode": "102",
      "attendanceOrgName": "研发部",
      "2026-05-01(五)": "九点班次",
      "2026-05-02(六)": "九点班次",
      "2026-05-03(日)": "九点班次",
      "2026-05-04(一)": "九点班次"
    },
    {
      "talentCode": "30183",
      "talentName": "田雨禾",
      "attendanceOrgCode": "103",
      "attendanceOrgName": "测试部",
      "2026-05-01(五)": "",
      "2026-05-02(六)": "",
      "2026-05-03(日)": "",
      "2026-05-04(一)": ""
    }
  ],
  "total": 21,
  "currPage": 1,
  "message": "ok",
  "messageType": 0
}
```

### 响应字段说明

**固定字段（每行都有）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| talentCode | String | 员工编码 |
| talentName | String | 员工姓名 |
| attendanceOrgCode | String | 考勤组织编码 |
| attendanceOrgName | String | 考勤组织名称 |

**动态日期字段：**

格式为 `yyyy-MM-dd(中文星期)`，例如 `2026-05-01(五)`。

| 字段 | 类型 | 说明 |
|------|------|------|
| 2026-05-01(五) | String | 有排班时返回班次名称，无排班时返回空字符串 |

星期映射：MONDAY→一，TUESDAY→二，WEDNESDAY→三，THURSDAY→四，FRIDAY→五，SATURDAY→六，SUNDAY→日。

### 分页信息

| 顶层字段 | 类型 | 说明 |
|----------|------|------|
| data | List\<Map\> | 员工行列表，每行一个 LinkedHashMap |
| total | Long | 符合条件的员工总数（不是日期数量） |
| currPage | Integer | 当前页码 |

### 参数校验

1. `startDate`、`endDate` 必填，格式 yyyy-MM-dd
2. `endDate` 不能小于 `startDate`
3. 日期范围最大 31 天
4. `pageNo` 默认 1
5. `pageSize` 默认 20，最大 200

### 权限规则

1. Controller 方法加 `@ScopeAuthRequired`
2. 普通员工只返回自己
3. 系统管理员：
   - `deptCode` 不传：不限制部门，查全部
   - `deptCode` 传：展开该部门及子部门后查询，不受 `deptScopes` 限制
4. 非系统管理员（HR/考勤员/部门负责人）：
   - `deptCode` 不传：使用 `ctx.getDeptScopes()` 作为查询范围
   - `deptCode` 传：按 `ctx.getDeptScopeTree()` 展开前端选择部门及子部门，再和 `ctx.getDeptScopes()` 取交集
   - 交集为空：返回空列表

### 查询规则

1. 只查有效考勤档案员工（`attendance_archive.status=1, is_deleted=0`）
2. 只查未删除且启用的排班记录（`attendance_schedule_day.is_deleted=0, status=1`）
3. 日期没有排班时，该日期列返回空字符串
4. 排班记录停用或删除：按无排班处理
5. 班次名称优先取 `attendance_shift_dict.shift_name`；没有关联班次时返回 `shift_code`；`shiftCode` 为空时返回空字符串
6. 员工行按 `attendanceOrgCode ASC, talentCode ASC` 排序

### 数据来源

| 数据 | 来源 |
|------|------|
| 员工列表 | `whd_attendance.attendance_archive a` JOIN `ip_db.talent_person p` JOIN `ip_db.talent_organization o` |
| 排班记录 | `whd_attendance.attendance_schedule_day sd` LEFT JOIN `whd_attendance.attendance_shift_dict s` |
| 部门过滤 | 使用 `a.attendance_org_code` 匹配 |

## 6. S6 单日排班编辑保存

`POST /api/attendance/schedule/list/update`

保存一个员工某一天的完整排班设置。包含两部分：
- **排班主信息**：保存到 `attendance_schedule_day`
- **班次时间段修订**（可选）：保存到 `attendance_schedule_time_revision` 和 `attendance_schedule_time_revision_detail`

页面只有一个保存按钮，主信息和段次时间列表一次性提交，后端一个事务处理，不会出现半成功状态。

### 请求参数

**主字段：**

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| scheduleDayId | 否 | Long | 已有日排班 ID（优先使用） |
| talentCode | 条件 | String | 员工编码（无 scheduleDayId 时必填） |
| scheduleDate | 条件 | String | 排班日期 yyyy-MM-dd（无 scheduleDayId 时必填） |
| dateType | 是 | String | 日期类型（工作日/休息日/节假日） |
| shiftCode | 是 | String | 班次编码 |
| attendancePolicyCode | 否 | String | 考勤制度编码，不传取档案默认值 |
| fetchCardRuleCode | 否 | String | 取卡规则编码，不传取班次默认值 |
| standardHours | 否 | BigDecimal | 标准工时，不传取班次默认值 |
| overtimeCompensateMode | 否 | String | 加班补偿方式，不传取班次默认值 |
| remark | 否 | String | 备注 |
| operatorId | 否 | String | 操作人 ID |
| operatorName | 否 | String | 操作人姓名 |

**段次修订字段（表单数组）：**

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| segments[N].segmentNo | 是 | Integer | 段次序号，从 1 开始 |
| segments[N].attendanceType | 否 | String | 出勤类型 |
| segments[N].startReferenceDate | 否 | String | 上班参考日期：当天/前一天/后一天 |
| segments[N].workStartTime | 是 | String | 上班时间，如 09:00 |
| segments[N].startNeedPunch | 是 | Integer | 上班是否打卡，1=是，0=否 |
| segments[N].startFloatMinutes | 否 | Integer | 上班浮动调整分钟 |
| segments[N].endReferenceDate | 否 | String | 下班参考日期：当天/前一天/后一天 |
| segments[N].workEndTime | 是 | String | 下班时间，如 18:00 |
| segments[N].endNeedPunch | 是 | Integer | 下班是否打卡，1=是，0=否 |
| segments[N].endFloatMinutes | 否 | Integer | 下班浮动调整分钟 |
| segments[N].restStartTime | 否 | String | 休息开始时间 |
| segments[N].restEndTime | 否 | String | 休息结束时间 |
| segments[N].restMinutes | 否 | Integer | 段内休息分钟数 |

### 请求示例

只保存排班主信息（不传 segments）：

```
Content-Type: application/x-www-form-urlencoded

scheduleDayId=10001&dateType=workday&shiftCode=S001&remark=手动调整
```

排班主信息 + 单段时间修订：

```
Content-Type: application/x-www-form-urlencoded

scheduleDayId=10001&dateType=workday&shiftCode=S001
```

| segmentCount | Integer | 写入段次数，未传 segments 时为 0 |
| message | String | 结果说明 |

### 权限规则

| 角色 | 是否可保存 |
|------|-----------|
| 考勤员 | 是（权限范围内） |
| 系统管理员 | 否（只读） |
| HR | 否（只读） |
| 部门负责人 | 否（只读） |
| 普通员工 | 否 |

### 保存规则

1. `scheduleDayId` 和 `talentCode + scheduleDate` 至少提供一组
2. 优先用 `scheduleDayId` 查找排班记录
3. 查不到排班记录直接失败
4. 必须存在排班记录才能编辑（不支持新增）
5. `sourceType` 固定写 `排班列表编辑`
6. `sourceBizType` 固定写 `单日排班编辑`
7. 如果 `segments` 为空，只保存排班主信息，不写时间修订
8. 如果 `segments` 不为空，校验每个段次必填字段后写入时间修订
9. 保存时间修订前，先逻辑删除该 `scheduleDayId` 旧的有效修订明细
10. 新增一条 `attendance_schedule_time_revision` 批次
11. 按 `segments` 列表逐条写入 `attendance_schedule_time_revision_detail`
12. 更新 `scheduleDay.sourceBizId = revisionId`
13. 全部操作在同一事务内完成

### 校验规则

1. `dateType`、`shiftCode` 必填
2. 排班记录必须存在
3. 员工必须存在于有效考勤档案
4. 班次必须存在且启用
5. 员工考勤组织必须在当前用户权限范围内
6. segments 校验（当 segments 不为空时）：
   - `segmentNo` 必填且 > 0
   - 同一次提交内 `segmentNo` 不允许重复
   - `workStartTime`、`workEndTime` 必填
   - `startNeedPunch`、`endNeedPunch` 必填

## 7. S7 调班

`POST /api/attendance/schedule/list/swap`

将两个日排班记录进行班次互换。不走审批流，不修改班次主数据。支持在一边无排班时自动生成休息日排班。

### 请求参数

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| sourceScheduleDayId | 否* | Long | 调出排班 ID（优先使用） |
| targetScheduleDayId | 否* | Long | 调入排班 ID（优先使用） |
| sourceTalentCode | 否* | String | 调出员工编码（无 ID 时使用） |
| sourceScheduleDate | 否* | String | 调出日期 yyyy-MM-dd（无 ID 时使用） |
| targetTalentCode | 否* | String | 调入员工编码（无 ID 时使用） |
| targetScheduleDate | 否* | String | 调入日期 yyyy-MM-dd（无 ID 时使用） |
| generateRestSchedule | 否 | Boolean | 是否允许生成休息日班次，默认 false |
| reason | 否 | String | 调班原因 |
| operatorId | 否 | String | 操作人 ID |
| operatorName | 否 | String | 操作人姓名 |

\* 调出和调入各至少提供一组标识：`scheduleDayId` 或 `(talentCode + scheduleDate)`

### 请求示例

```
Content-Type: application/x-www-form-urlencoded

sourceScheduleDayId=10001&targetScheduleDayId=10002&generateRestSchedule=false&reason=临时调整&operatorId=90001&operatorName=考勤员
```

### 响应

```json
{
  "success": true,
  "data": {
    "success": true,
    "sourceScheduleDayId": 10001,
    "targetScheduleDayId": 10002,
    "sourceTalentCode": "30028",
    "targetTalentCode": "60071",
    "sourceScheduleDate": "2026-05-01",
    "targetScheduleDate": "2026-05-01",
    "message": "调班成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 权限规则

只有考勤员可以调班。系统管理员、HR、部门负责人、普通员工均禁止。

### 互换字段

调班时互换：`shiftCode`、`dateType`、`attendancePolicyCode`、`fetchCardRuleCode`、`standardHours`、`overtimeCompensateMode`、`remark`

不互换：`scheduleDayId`、`talentCode`、`scheduleDate`、`groupId`

### 查找规则

1. 优先用 `sourceScheduleDayId` 查调出排班
2. 没有 `sourceScheduleDayId` 时，用 `sourceTalentCode + sourceScheduleDate` 查调出排班
3. 调入同理
4. 用 talentCode+date 查不到时返回 null（可能触发休息日生成）

### 班次校验

| 场景 | 处理 |
|------|------|
| 两边都有排班，班次不同 | 直接互换 |
| 两边都有排班，班次相同 | 禁止 |
| 一边有排班，一边无排班，`generateRestSchedule=true` | 先生成休息日排班，再互换 |
| 一边有排班，一边无排班，`generateRestSchedule=false` | 抛异常 |
| 两边都无排班 | 禁止 |

### 休息日生成规则

生成休息日记录时写入：

| 字段 | 值 |
|------|-----|
| scheduleDayId | 新生成 ID |
| talentCode | 对应员工编码 |
| scheduleDate | 对应日期 |
| shiftCode | 空字符串 |
| dateType | `休息日` |
| sourceType | `调班` |
| sourceBizType | `排班列表调班-休息日生成` |
| status | `1` |
| isDeleted | `0` |
| remark | `调班自动生成休息日班次` |

生成前必须校验该员工存在有效考勤档案且在当前用户权限范围内。

### 调班规则

1. 不能是同一条记录
2. 两条记录对应员工都必须在权限范围内
3. 更新后 `sourceType=调班`、`sourceBizType=排班列表调班`
4. 事务内更新两条记录并写入调班历史
5. 任意失败整体回滚

### 调班历史

每次调班写入 `attendance_schedule_swap_history` 表，包含：

- 调出/调入的 scheduleDayId、talentCode、talentName、scheduleDate
- 调班前后的快照 JSON
- 操作人和调班原因

## 8. S8 排班时间修订

### 请求参数

### 核心规则

1. 只修订已有排班，不创建未排班记录
2. 不修改班次模板、不改变 shiftCode
3. 修订后 `sourceType=时间修订`

## 11. S9 排班列表导出

| 排班状态 | 单元格内容示例 |
|----------|---------------|
| 单段班次（无修订） | `早班 09:00-18:00` |
| 多段班次（无修订） | `早班 09:00-12:00 / 13:00-18:00` |
| 有时间修订 | `早班 08:30-17:30`（取修订后时间） |
| 休息日 | `休息` |
| 无排班（有档案默认班次） | 取档案默认班次名称 + 时间 |
| 无排班（无默认班次） | `未排班` |
| 无班次编码（非休息日） | `未排班` |

### 权限规则

| 角色 | 是否可导出 |
|------|-----------|
| 系统管理员 | 是（全部数据） |
| HR | 是（权限范围内） |
| 考勤员 | 是（权限范围内） |
| 部门负责人 | 是（权限范围内） |
| 普通员工 | 否 |

### 导出规则

#### SELECTED 模式

1. `selectedTalentCodes` 必填，上限 500 人
2. 逐个校验员工是否在当前用户权限范围内，越权抛异常
3. 系统管理员跳过员工权限校验

#### ALL 模式

1. 按 S2 横向列表同一套查询和权限口径
2. 有 `shiftCode` 时：使用 `listMatchingScheduleDays` 查询命中记录
3. 无 `shiftCode` 时：先 `countHorizontalPage` 校验数量，再 `listHorizontalPage` 分页获取（上限 10000）
4. 有 `talentName` 时：先通过 IPS 模糊匹配员工编码
5. 数据量超过 10000 条时抛异常，提示缩小筛选范围
6. 无匹配数据时抛异常

### 参数校验

1. `exportScope` 只允许 `SELECTED` 或 `ALL`
2. `startDate`、`endDate` 必填
3. `endDate` 不能小于 `startDate`
4. 日期跨度最大 31 天
5. SELECTED 模式下 `selectedTalentCodes` 必填且不超过 500
6. `deptCode` 不在用户权限范围内时抛异常

### 数据来源

| 数据 | 来源 |
|------|------|
| 员工编码/姓名 | IPS `talent_person` |
| 组织编码/名称 | 考勤档案 + IPS `talent_organization` |
| 考勤组 | `attendance_group_member` + `attendance_group` |
| 日排班 | `attendance_schedule_day` |
| 班次名称 | `attendance_shift_dict` |
| 班次上下班时间 | 优先取 `attendance_schedule_time_revision_detail`（时间修订），无修订取 `attendance_shift_detail`（班次模板） |
| 默认班次 | `attendance_archive.defaultShiftCode`（无日排班时兜底） |
