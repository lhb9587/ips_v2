# 出勤记录接口

基础路径：`/api/attendance/record`

统一返回结构：`ReturnInfo<T>`

公共规则：
- Content-Type：`application/x-www-form-urlencoded`
- tokenID 通过 query 参数或请求头传入
- 涉及数据权限的接口必须标注 `@ScopeAuthRequired`
- 分页接口返回时，`data` 直接放列表，`total` 放总数，`currPage` 放当前页

---

## 1. 出勤记录聚合分页查询

`POST /api/attendance/record/page`

按组织、姓名、日期范围查询员工逐日出勤聚合记录。

记录粒度：`员工 + 出勤日期`。

该接口只读，不写库。当前实现读取 `whd_attendance.attendance_calendar_day_snapshot` 汇总快照表，不实时重新计算出勤结果。

### 查询条件

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deptCode | String | 否 | 组织编码；为空时查询当前用户权限范围内全部组织；非空时按当前用户权限树展开子部门后查询 |
| talentName | String | 否 | 员工姓名，模糊查询 |
| startDate | String | 否 | 开始日期，格式 `yyyy-MM-dd`；为空默认当天 |
| endDate | String | 否 | 结束日期，格式 `yyyy-MM-dd`；为空默认当天 |
| queryType | String | 否 | 查询方式，当前保留字段，默认 `all`，暂不参与过滤 |
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 20，最大 200 |

### 返回字段

| 字段 | 说明 |
|------|------|
| recordKey | 出勤快照记录 ID，前端列表唯一键 |
| attendanceDate | 出勤日期，格式 `yyyy-MM-dd` |
| talentCode | 员工编码 |
| talentName | 员工姓名 |
| deptCode | 组织编码 |
| deptName | 组织名称 |
| positionName | 职位名称，当前实现返回空 |
| punchRecords | 打卡记录摘要，对应 `attendance_calendar_day_snapshot.punch_summary` |
| punchCount | 打卡次数 |
| punchSource | 打卡来源摘要，对应 `attendance_calendar_day_snapshot.punch_source_summary` |
| supplementRecords | 补签卡记录摘要，对应 `attendance_calendar_day_snapshot.supplement_summary` |
| leaveSummary | 请假摘要，对应 `attendance_calendar_day_snapshot.leave_summary` |
| businessTripSummary | 出差摘要，对应 `attendance_calendar_day_snapshot.trip_summary` |
| overtimeSummary | 加班摘要，对应 `attendance_calendar_day_snapshot.overtime_summary` |

### 返回示例

```json
{
  "success": true,
  "data": [
    {
      "recordKey": 10001,
      "attendanceDate": "2026-05-12",
      "talentCode": "10030",
      "talentName": "李丹",
      "deptCode": "13401",
      "deptName": "万慧达_行政与人力资源部_行政与人力资源部-北京",
      "positionName": null,
      "punchRecords": "08:56,18:03",
      "punchCount": 2,
      "punchSource": "导入",
      "supplementRecords": "",
      "leaveSummary": "事假 2小时",
      "businessTripSummary": "",
      "overtimeSummary": "加班 1小时"
    }
  ],
  "total": 1,
  "currPage": 1,
  "message": "ok",
  "messageType": 0
}
```

### 处理规则

1. 系统管理员可查询全部。
2. HR、考勤员、部门负责人按权限范围查询。
3. 普通员工返回空列表。
4. `deptCode` 为空时，使用当前用户 `deptScopes` 查询。
5. `deptCode` 不为空时，非系统管理员按 `deptScopeTree` 展开子部门，再和当前用户 `deptScopes` 取交集。
6. `startDate` 为空默认当天。
7. `endDate` 为空默认当天。
8. `startDate` 不能大于 `endDate`。
9. 查询日期范围最大 31 天。
10. `pageSize` 最大 200。
11. 只查询 `attendance_calendar_day_snapshot.is_deleted = 0` 的记录。
12. 返回结果按 `attendanceDate DESC, talentCode ASC` 排序。
13. 当前接口不返回打卡、请假、出差、加班的明细列表，只返回快照摘要字段。

## 2. 单员工单日出勤详情

`POST /api/attendance/record/detail`

查询某个员工某一天的出勤组成明细。

用于前端点击出勤记录列表某一行后查看完整明细。

当前接口未完成。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| talentCode | String | 是 | 员工编码 |
| attendanceDate | String | 是 | 出勤日期，格式 `yyyy-MM-dd` |

### 返回字段

| 字段 | 说明 |
|------|------|
| talentCode | 员工编码 |
| talentName | 员工姓名 |
| deptCode | 组织编码 |
| deptName | 组织名称 |
| attendanceDate | 出勤日期 |
| punchRecords | 打卡明细列表 |
| supplementRecords | 补签卡明细列表 |
| leaveRecords | 请假明细列表 |
| businessTripRecords | 出差明细列表 |
| overtimeRecords | 加班明细列表 |

### 规则

1. 当前用户必须对该员工所属组织有权限。
2. 该接口只读，不写库。
3. 打卡、补签、请假、出差、加班分别返回明细列表。
