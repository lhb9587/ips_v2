## 1. 请假单列表分页查询

`POST /api/leave/request/admin/page`

### 作用

后台管理端查询请假单列表，支持按权限范围筛选。

### 权限规则

- 系统管理员可查全部。
- HR、考勤员、部门负责人、组长按权限部门范围查询。
- 传 `deptCode` 时，展开父部门及全部子部门，再与当前用户部门权限范围取交集。
- 普通员工不开放后台入口，返回空列表。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `requestNo` | String | 否 | 单据编号模糊查询 |
| `talentCode` | String | 否 | 员工编码 |
| `talentName` | String | 否 | 姓名模糊查询 |
| `deptCode` | String | 否 | 组织编码，支持父部门筛选 |
| `leaveTypeCode` | String | 否 | 假期类型编码 |
| `requestStatus` | String | 否 | 单据状态：未提交、审批中、已通过、已退回 |
| `approvalStatus` | String | 否 | 审批状态：审批中、已通过、已退回 |
| `startDate` | String | 否 | 请假开始日期 |
| `endDate` | String | 否 | 请假结束日期 |
| `pageNo` | Integer | 否 | 页码，默认 1 |
| `pageSize` | Integer | 否 | 每页条数，默认 20，最大 200 |

### 返回字段

## 2. 请假单详情查询

`POST /api/leave/request/admin/detail`

### 作用

统一详情查询入口（后台管理端 + 员工自助共用）。返回基础信息、请假明细、附件、审批信息和操作权限按钮。

### 权限规则

- 查看不拦：所有登录用户均可查看任意请假单详情。
- 操作按钮按身份和单据状态计算：
  - `canApprove`/`canReject`：当前登录人是当前待审批人时为 true。
  - `canSubmit`/`canEdit`：申请人本人查看未提交/已退回单据时为 true。
  - `canDelete`：申请人本人查看未提交草稿时为 true。
  - `canAbandon`：申请人本人查看审批中单据且审批实例无人审批过时为 true。`canAbandon` 在本系统中不是作废单据，而是申请人撤回审批；执行后请假单状态回到 `未提交`。
  - `canDirectPass`/`canReverseApprove`：考勤员/管理员按后台规则。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `leaveRequestId` | Long | 是 | 请假单ID |

### 返回字段

基础信息：

## 3. 请假单提交生效

`POST /api/leave/request/admin/direct-pass`

### 作用

后台考勤员/管理员将未提交或已退回的请假单直接通过审批，绕过正常审批流程，不生成待审批任务。请假单状态直接变为"已通过"。

### 权限规则

- 需 `@ScopeAuthRequired`，系统管理员、HR、考勤员可操作。
- 操作对象必须在当前用户部门权限范围内。
- 操作人固定取当前登录用户，不使用前端传值。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `leaveRequestId` | Long | 是 | 请假单ID（request_id） |
| `leaveRequestIds` | String | 否 | 批量请假单ID，逗号分隔，优先使用；不传则使用 leaveRequestId |
| `remark` | String | 否 | 备注 |
| `operatorId` | String | 否 | 保留字段，不使用 |
| `operatorName` | String | 否 | 保留字段，不使用 |

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `leaveRequestId` | Long | 请假单ID |
| `requestNo` | String | 请假单号 |
| `approvalInstanceId` | Long | 审批实例ID |
| `approvalStatus` | String | 固定"已通过" |
| `requestStatus` | String | 固定"已通过" |
| `submitActionId` | Long | 提交动作日志ID |
| `approveActionId` | Long | 通过动作日志ID |
| `quotaProcessed` | Boolean | 是否已处理额度 |
| `success` | Boolean | 批量操作是否成功 |
| `successCount` | Integer | 成功操作条数 |
| `leaveRequestIds` | List&lt;Long&gt; | 本次操作的请假单ID列表 |

### 业务规则

1. 只允许状态为"未提交"或"已退回"的请假单执行提交生效。
2. 调用审批中心直接通过服务（`ApprovalWorkflowDirectPassService`），写入审批实例、提交日志、通过日志，不生成待审批任务。
3. 提交生效后自动处理额度扣除。
4. 审批提交和额度处理在同一事务中，任一失败全部回滚。

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| leaveRequestId 为空 | leaveRequestId 不能为空 |
| 无操作权限 | 无权操作提交生效 |
| 请假单不存在 | 请假单不存在 |
| 部门权限不足 | 无权操作该请假单 |
| 状态不是未提交或已退回 | 当前状态不允许提交生效，当前状态：xxx |

### 返回示例

```json
{
  "success": true,
  "data": {
    "leaveRequestId": 20260424090001,
    "requestNo": "QJ20260424001",
    "approvalInstanceId": 10002,
    "approvalStatus": "已通过",
    "requestStatus": "已通过",
    "submitActionId": 40003,
    "approveActionId": 40004,
    "quotaProcessed": true
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

## 4. 请假单反审批

`POST /api/leave/request/admin/reverse-approve`

### 作用

后台考勤员/管理员将已通过的请假单撤回为未提交状态。写入撤回日志，更新审批实例状态为"已撤回"，禁用审批绑定，回退额度。

### 权限规则

- 需 `@ScopeAuthRequired`，系统管理员、HR、考勤员可操作。
- 操作对象必须在当前用户部门权限范围内。
- 操作人固定取当前登录用户，不使用前端传值。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `leaveRequestId` | Long | 是 | 请假单ID（request_id） |
| `leaveRequestIds` | String | 否 | 批量请假单ID，逗号分隔，优先使用；不传则使用 leaveRequestId |
| `remark` | String | 否 | 备注 |
| `operatorId` | String | 否 | 保留字段，不使用 |
| `operatorName` | String | 否 | 保留字段，不使用 |

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `leaveRequestId` | Long | 请假单ID |
| `requestNo` | String | 请假单号 |
| `approvalInstanceId` | Long | 审批实例ID |
| `beforeStatus` | String | 反审批前状态，固定"已通过" |
| `afterStatus` | String | 反审批后状态，固定"未提交" |
| `reverseActionId` | Long | 撤回动作日志ID |
| `quotaProcessed` | Boolean | 是否已处理额度回退 |
| `success` | Boolean | 批量操作是否成功 |
| `successCount` | Integer | 成功操作条数 |
| `leaveRequestIds` | List&lt;Long&gt; | 本次操作的请假单ID列表 |

### 业务规则

1. 只允许审批状态为"已通过"的请假单执行反审批。
2. 请假已开始（startTime <= 当前时间）不允许反审批。
3. 必须存在审批实例。
4. 写入撤回审批日志（actionType="撤回"，actionResult="未提交"）。
5. 更新审批实例状态为"已撤回"。
6. 更新请假单状态为"未提交"。
7. 额度回退：先处理额度回退，再禁用审批绑定（额度服务依赖当前绑定）。
8. 禁用旧的审批绑定关系。
9. 审批撤回、状态更新、额度回退、禁用绑定在同一事务中，任一失败全部回滚。

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| leaveRequestId 为空 | leaveRequestId 不能为空 |
| 无操作权限 | 无权操作反审批 |
| 请假单不存在 | 请假单不存在 |
| 部门权限不足 | 无权操作该请假单 |
| 审批状态不是已通过 | 当前状态不允许反审批，当前审批状态：xxx |
| 无审批实例 | 未找到审批实例 |
| 请假已开始 | 请假已开始，无法反审批 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "leaveRequestId": 20260424090001,
    "requestNo": "QJ20260424001",
    "approvalInstanceId": 10001,
    "beforeStatus": "已通过",
    "afterStatus": "未提交",
    "reverseActionId": 40005,
    "quotaProcessed": true
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

## 7. 【我要请假】请假申请初始化

`POST /api/leave/request/self/init`

### 作用

员工自助请假页面打开时初始化，返回当前员工信息、可选假期类型、当前周期额度余额。前端用于渲染请假表单的基础数据。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。
- 不传 `talentCode` 时固定取当前登录用户；传了则按 `talentCode` 查目标员工。
- 不写库，纯查询。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `talentCode` | String | 否 | 员工编码。不传时返回当前登录员工初始化内容；传了返回指定员工初始化内容 |

### 返回字段

`ReturnInfo<LeaveRequestSelfInitVO>`

员工信息（`employee`）：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `userId` | Integer | IPS 用户 ID |
| `talentCode` | String | 员工编码 |
| `talentName` | String | 员工姓名 |
| `deptCode` | String | 部门编码 |
| `deptName` | String | 部门全称（kingDeeFullGroupName） |
| `empStatus` | String | 用工状态 |

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `applyDate` | Date | 默认申请日期，当前日期 |

假期类型列表（`leaveTypes`）：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `leaveTypeCode` | String | 假期类型编码 |
| `leaveTypeName` | String | 假期类型名称 |
| `isNoQuota` | Boolean | 是否无额度假 |
| `isAttachmentRequired` | Boolean | 是否提交时必须附件 |
| `description` | String | 假期类型描述 |
| `sort` | Integer | 排序号 |
| `quotaAccountId` | Long | 当前周期额度账户 ID（无则为 null） |
| `actualQuota` | BigDecimal | 实际额度 |
| `usedQuota` | BigDecimal | 已用额度 |
| `frozenQuota` | BigDecimal | 冻结/在途额度 |
| `remainQuota` | BigDecimal | 剩余额度 |
| `quotaUnit` | String | 额度单位 |
| `periodStartDate` | Date | 周期开始日期 |
| `periodEndDate` | Date | 周期结束日期 |
| `canApply` | Boolean | 是否可申请 |
| `disabledReason` | String | 不可申请原因 |

### 业务规则

1. 员工查询：`talent_person` LEFT JOIN `talent_organization`，按 `userId` 匹配。

## 8. 【我要请假】请假时长试算

`POST /api/leave/request/self/calc-duration`

### 作用

按当前登录员工、假期类型、开始时间、结束时间，试算请假时长，并返回当前假期额度是否足够。前端用于实时预览请假时长和额度提示。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。

- 不允许前端传 `duration`，时长必须后端计算。

| ---- | ---- | ---- | ---- |
| `leaveTypeCode` | String | 是 | 假期类型编码 |
| `startTime` | String | 是 | 请假开始时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `endTime` | String | 是 | 请假结束时间，格式 `yyyy-MM-dd HH:mm:ss` |

### 返回字段

`ReturnInfo<LeaveRequestSelfCalcDurationVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |

### 时长计算规则（半天单位，第一版固定规则）

| 口径 | 假期类型 | 规则 |

| 规则 | 时间 |

| 日期位置 | 规则 |
| ---- | ---- |

| 中间完整日 | 每天 1 天 |
| 结束日 | 结束时间 > 14:00 → 1 天，> 09:00 且 <= 14:00 → 0.5 天，<= 09:00 → 0 天 |

## 9. 【我要请假】保存请假草稿（支持保存并提交）

`POST /api/leave/request/self/save`

### 作用

员工自助保存请假草稿，支持新建和更新已有草稿。通过 `actionType` 参数同时支持保存后提交审批，前端只需调这一个接口。

- `actionType` 为空或 `save`：只保存草稿，不触发审批流程。
- `actionType=submit`：先保存草稿，再提交审批。保存和提交在同一事务中，提交失败时保存也回滚。

原 `POST /api/leave/request/self/submit` 保留兼容，可继续单独使用。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。
- 不允许前端传 `talentCode`，固定取当前登录用户。
- `requestId` 为空时新建草稿，非空时更新已有草稿。
- 更新时校验归属和状态，允许更新自己的"未提交"或"已退回"请假单。已退回单据保存后状态回到"未提交"，旧审批绑定被禁用。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `requestId` | Long | 否 | 请假单ID，空则新建，非空则更新 |
| `leaveTypeCode` | String | 是 | 假期类型编码 |
| `startTime` | String | 是 | 请假开始时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `endTime` | String | 是 | 请假结束时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `reason` | String | 否 | 请假事由 |
| `remark` | String | 否 | 备注 |
| `actionType` | String | 否 | 操作类型：`save`=保存草稿，`submit`=保存并提交。为空默认 `save` |
| `attachmentIds` | String | 否 | 附件ID，逗号分隔，如 `1001,1002` |

### 返回字段

`ReturnInfo<LeaveRequestSelfSaveActionResultVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `leaveRequestId` | Long | 请假单ID |
| `requestNo` | String | 请假单号 |
| `actionType` | String | 本次操作类型 |
| `saved` | Boolean | 固定 `true` |
| `submitted` | Boolean | `actionType=save` 时为 `false`，`actionType=submit` 时为 `true` |
| `approvalInstanceId` | Long | 审批实例ID（仅 `actionType=submit` 时返回） |
| `approvalTaskId` | Long | 审批任务ID（仅 `actionType=submit` 时返回） |
| `status` | String | 单据状态：`save` 时为"未提交"，`submit` 时为"审批中" |

### 业务规则

1. 新建时自动生成 `requestId`（`System.currentTimeMillis() * 1000 + 序列号`）和 `requestNo`（`QJ + yyyyMMddHHmmssSSS + 3位序列`）。
2. 请假时长由后端计算（调用 `LeaveRequestSelfCalcDurationService.calcDuration()`），前端不传。
3. 新建时自动生成一条请假明细（`detail_id` 同样使用业务ID生成规则）。
4. 更新时先删除旧明细再重新插入。
5. 附件处理：先逻辑删除该请假单下所有附件关系，再批量插入 `attachmentIds` 中的附件关系。
6. `attachmentIds` 格式错误时抛"附件ID格式错误"。
7. 数据库插入/更新/删除均校验影响行数，异常时抛出 BusinessException。
8. `actionType=submit` 时，编排 Service 先调用保存再调用提交，两者在同一事务中。提交失败时保存也回滚，不会留下脏数据。
9. `actionType=submit` 时，提交校验（状态、附件、额度、时长）复用 `LeaveRequestSelfSubmitService.submit()` 内的全部校验。

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| 请求参数为空 | 请求参数不能为空 |
| actionType 非法值 | actionType 参数错误 |
| leaveTypeCode 为空 | 假期类型编码不能为空 |
| startTime 为空 | 开始时间不能为空 |
| endTime 为空 | 结束时间不能为空 |
| 时间格式不合法 | 时间格式错误，正确格式为 yyyy-MM-dd HH:mm:ss |
| endTime <= startTime | 结束时间必须晚于开始时间 |
| userId 无员工 | 当前登录用户未找到员工信息 |
| talentCode 为空 | 当前登录用户员工编码为空 |
| 假期类型不存在或已停用 | 假期类型不存在或已停用 |
| 更新时请假单不存在 | 请假单不存在 |
| 更新时非本人草稿 | 不允许修改其他员工的请假单 |

## 13. 【我要请假】删除请假草稿

`POST /api/leave/request/self/delete`

### 作用

当前登录员工删除自己的未提交或已退回请假单。支持批量删除，逻辑删除主表、明细、附件关系。已提交、审批中、已通过的单据不允许删除。删除已退回单据时自动禁用旧审批绑定。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。
- 不接收 `talentCode`，固定取当前登录用户。
- 只允许删除自己的未提交或已退回的单据。
- 不物理删除，仅逻辑删除（`is_deleted = 1`）。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `leaveRequestId` | Long | 否 | 请假单业务ID，兼容单条 |
| `leaveRequestIds` | String | 否 | 请假单业务ID，批量，逗号分隔，优先使用 |

两个参数至少传一个。`leaveRequestIds` 优先级高于 `leaveRequestId`。

### 返回字段

`ReturnInfo<LeaveRequestSelfDeleteResultVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `successCount` | Integer | 成功删除数量 |
| `leaveRequestIds` | List\<Long\> | 成功删除的请假单 ID 列表 |
| `deleted` | Boolean | 是否删除成功 |
| `leaveRequestId` | Long | 兼容：第一条请假单 ID |
| `requestNo` | String | 兼容：第一条请假单号 |

### 业务规则

1. 校验归属：所有请假单的 `talentCode` 必须等于当前员工 `talentCode`。
2. 校验状态：只允许删除 `未提交` 或 `已退回` 的单据。
3. 逻辑删除主表（`attendance_leave_request`），SQL 带 `talent_code` 和 `status IN ('未提交', '已退回')` 条件防止并发状态变化后误删。
4. 逻辑删除明细（`attendance_leave_request_detail`），允许 0 行（兼容脏数据）。
5. 逻辑删除附件关系（`attendance_leave_request_attachment`），允许 0 行（附件可选）。
6. 事务保证：主表/明细/附件在同一事务中，任一失败全部回滚。
7. 已退回单据删除时，自动禁用旧审批绑定（`approval_biz_rel.is_current` 置为 0）。
8. 批量操作时，任意一条校验失败则整体回滚，所有记录均不删除。
9. ID 自动去重，最多允许 100 条。

| 请假单不存在 | 请假单不存在 |

| 非未提交/已退回状态 | 只允许删除未提交或已退回的请假单 |

### 权限规则

- 仅校验 token，不加 `@ScopeAuthRequired`。
- 使用 `@RequestParam("file")` 接收文件，不使用 `@RequestBody`。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `file` | MultipartFile | 是 | 上传文件 |
| `bizType` | String | 否 | 业务类型，默认 `common` |

### 返回字段

`ReturnInfo<AttachmentUploadVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `attachmentId` | Long | 附件ID，业务接口通过此 ID 关联 |
| `fileName` | String | 原始文件名 |
| `filePath` | String | 前端访问路径 |
| `fileType` | String | 文件扩展名：jpg、png、pdf 等 |
| `fileSize` | Long | 文件大小（字节） |
| `uploadTime` | String | 上传日期，格式 `yyyy-MM-dd` |

### 文件保存规则

1. 物理路径：`${fileUrl}/template/attendance/yyyy-MM-dd/时间戳/文件名`
2. 返回路径：`/template/attendance/yyyy-MM-dd/时间戳/文件名`
3. 自动创建日期目录和时间戳目录。

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| file 为空或空文件 | 上传文件不能为空 |
| 文件超过 20MB | 文件大小不能超过20MB |
| 文件名不含扩展名 | 文件缺少扩展名 |
| 不支持的文件类型 | 不支持的文件类型，允许：jpg、jpeg、png、pdf、doc、docx、xls、xlsx |
| 文件名含路径字符 | 自动清理 `../`、`/`、`\`，不会拒绝但会重命名 |
| 写库失败 | 保存附件记录失败（同时删除已落盘文件） |

### 允许的文件类型

| 类型 | 扩展名 |
| ---- | ------ |
| 图片 | jpg、jpeg、png |
| 文档 | pdf、doc、docx |
| 表格 | xls、xlsx |

## 15. 【我要请假】废弃请假单

`POST /api/leave/request/self/abandon`

### 作用

当前登录员工废弃自己的已提交请假单。支持批量废弃。用于"我不想继续这张请假单了"，不是删除草稿。

与删除草稿的区别：
- `self/delete` 只处理 `未提交` 草稿，逻辑删除。
- `self/abandon` 处理已经进入业务流程的请假单，把状态改成 `已废弃`，并同步处理审批和额度。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。
- 不允许前端传 `talentCode`，固定取当前登录用户。
- 只能废弃自己的请假单。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `leaveRequestId` | Long | 否 | 请假单业务ID，兼容单条 |
| `leaveRequestIds` | String | 否 | 请假单业务ID，批量，逗号分隔，优先使用 |
| `remark` | String | 否 | 废弃原因 |

两个 ID 参数至少传一个。`leaveRequestIds` 优先级高于 `leaveRequestId`。

### 返回字段

`ReturnInfo<LeaveRequestSelfAbandonResultVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `successCount` | Integer | 成功废弃数量 |
| `leaveRequestIds` | List\<Long\> | 成功废弃的请假单 ID 列表 |
| `abandoned` | Boolean | 是否废弃成功 |
| `leaveRequestId` | Long | 兼容：第一条请假单 ID |
| `requestNo` | String | 兼容：第一条请假单号 |

### 业务规则

1. **未提交**：不允许废弃，使用删除功能。
2. **审批中**：允许废弃（撤回审批），但必须无人同意/退回过。废弃后请假单状态回到 `未提交`，审批实例状态置为 `已撤回`。释放冻结额度。
3. **已退回**：不允许废弃，编辑后重新提交。
4. **已通过**：不允许员工端废弃。
5. **已废弃**：不允许重复操作。
6. 操作人信息从登录上下文获取，不依赖前端传参。
7. 事务保证：审批终止和额度处理在同一事务中，任一失败全部回滚。
8. 批量操作时，先校验所有记录，任意一条校验失败则整体回滚，所有记录均不废弃。
9. ID 自动去重，最多允许 100 条。

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| request 为空 | 请求参数不能为空 |
| leaveRequestId 和 leaveRequestIds 都为空 | leaveRequestId 不能为空 |
| leaveRequestIds 格式错误 | leaveRequestIds 格式错误 |
| 超过 100 条 | 单次最多允许操作 100 条 |
| userId 无员工 | 当前登录用户未找到员工信息 |
| talentCode 为空 | 当前登录用户员工编码为空 |
| 请假单不存在 | 请假单不存在 |
| 非本人单据 | 无权废弃该请假单 |
| 未提交状态 | 未提交草稿请使用删除功能 |
| 已废弃状态 | 请假单已废弃，不可重复操作 |
| 已通过且已开始 | 请假已开始，无法废弃 |
