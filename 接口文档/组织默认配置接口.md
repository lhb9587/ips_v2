# 组织默认配置接口

用于管理和查询组织默认配置（默认考勤制度、假期制度、班次编码）。配置数据来源于 IPS 组织表的增量同步，制度编码由管理员在后台手动维护。

---

## 1. 手动触发增量同步

从 IPS talent_organization 同步有效组织到 attendance_org_default_config。同步规则：新组织新增，已有组织仅更新 remark/status/update_time，不覆盖已配置的制度/班次编码。幂等操作。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/admin/org-default-config/sync` |
| Content-Type | `application/json` |
| 鉴权要求 | 需要登录（tokenID） |

### 请求参数

无。

### 响应体

#### 成功响应

```json
{
  "success": true,
  "data": {
    "affectedRows": 15,
    "message": "同步完成"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `affectedRows` | Integer | 受影响行数（新增 + 更新） |
| `message` | String | 结果描述 |

---

## 2. 按员工批量查询组织默认配置

输入员工编码列表，返回每个员工所属组织的默认考勤制度、假期制度、班次编码，以及配置完整性检查。返回顺序与请求 talentCodes 顺序一致。部分员工缺配置不报错，逐条返回缺失信息。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/admin/org-default-config/query-by-employees` |
| Content-Type | `application/json` |
| 鉴权要求 | 需要登录（tokenID） |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `talentCodes` | String[] | 是 | 员工编码列表 |

### 请求示例

```json
{
  "talentCodes": ["30028", "60071", "99999"]
}
```

### 响应体

#### 成功响应

```json
{
  "success": true,
  "data": [
    {
      "talentCode": "30028",
      "talentName": "张三",
      "deptCode": "101",
      "deptName": "技术部/后端组",
      "attendancePolicyCode": "POLICY001",
      "leavePolicyCode": "LEAVE001",
      "defaultShiftCode": "SHIFT001",
      "configComplete": true,
      "missingFields": null
    },
    {
      "talentCode": "60071",
      "talentName": "李四",
      "deptCode": "205",
      "deptName": "市场部",
      "attendancePolicyCode": "POLICY002",
      "leavePolicyCode": null,
      "defaultShiftCode": "SHIFT002",
      "configComplete": false,
      "missingFields": "缺少：假期制度"
    },
    {
      "talentCode": "99999",
      "talentName": null,
      "deptCode": null,
      "deptName": null,
      "attendancePolicyCode": null,
      "leavePolicyCode": null,
      "defaultShiftCode": null,
      "configComplete": false,
      "missingFields": "员工信息不存在"
    }
  ],
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `talentCode` | String | 员工编码 |
| `talentName` | String | 员工姓名，员工不存在时为 null |
| `deptCode` | String | 所属组织编码，未关联组织时为 null |
| `deptName` | String | 所属组织全称 |
| `attendancePolicyCode` | String | 默认考勤制度编码，未配置时为 null |
| `leavePolicyCode` | String | 默认假期制度编码，未配置时为 null |
| `defaultShiftCode` | String | 默认班次编码，未配置时为 null |
| `configComplete` | Boolean | 三个编码是否都不为空 |
| `missingFields` | String | 缺失说明：如"缺少：假期制度、默认班次"，完整时为 null |

#### 失败响应

仅参数格式错误时抛异常：

```json
{
  "success": false,
  "data": null,
  "total": null,
  "currPage": null,
  "message": "talentCodes 不能为空",
  "messageType": 10001
}
```

### 调用示例

```bash
curl -X POST "http://localhost:9091/api/admin/org-default-config/query-by-employees?tokenID=xxx" \
  -H "Content-Type: application/json" \
  -d '{"talentCodes":["30028","60071"]}'
```

---

## 附录：查询链路

```
请求 talentCodes
  → ipdb: talent_person LEFT JOIN talent_organization（获取员工姓名 + 组织名称）
  → whd:  attendance_org_default_config WHERE dept_code IN(...)（获取默认配置）
  → Java 侧拼装，按请求顺序返回
```
