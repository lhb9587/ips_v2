## 2. 假期额度列表分页

分页查询当前用户权限范围内的员工假期额度账户列表。员工姓名、组织名称、假期类型名称通过跨库 JOIN 补充，不写库。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/leave/quota/account/page` |
| Content-Type | `application/x-www-form-urlencoded` |
| 鉴权要求 | 需要登录（tokenID） + 数据权限范围（@ScopeAuthRequired） |

### 权限规则

| 角色 | 数据范围 |
|------|----------|
| 系统管理员 | 查询全部 |
| HR / 考勤员 / 部门负责人 | 按当前用户 `deptScopes` 过滤；前端传 `deptCodes` 时与权限取交集；无 `deptScopes` 时返回空分页 |
| 普通员工 | 不开放，直接返回空分页 |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tokenID` | String | 是 | 统一鉴权令牌 |
| `talentCode` | String | 否 | 员工编码，模糊查询 |
| `talentName` | String | 否 | 员工姓名，模糊查询 |
| `deptCodes` | String[] | 否 | 组织编码列表，与当前用户权限部门取交集 |
| `leaveTypeCode` | String | 否 | 假期类型编码，精确匹配 |
| `empStatus` | String | 否 | 用工状态，不传默认 `在职` |
| `auditStatus` | String | 否 | 审核状态，如 `未审核`、`已审核` |
| `quotaStatus` | String | 否 | 额度状态，如 `生效`、`失效`、`作废` |
| `periodStartDateFrom` | String | 否 | 周期开始日期起，格式 `yyyy-MM-dd` |
| `periodStartDateTo` | String | 否 | 周期开始日期止，格式 `yyyy-MM-dd` |
| `periodEndDateFrom` | String | 否 | 周期结束日期起，格式 `yyyy-MM-dd` |
| `periodEndDateTo` | String | 否 | 周期结束日期止，格式 `yyyy-MM-dd` |
| `onlyRemainPositive` | Integer | 否 | 是否只看剩余额度大于 0：`1` 是，`0` 否 |
| `pageNo` | Integer | 否 | 页码，默认 `1` |
| `pageSize` | Integer | 否 | 每页条数，默认 `20`，最大 `200` |

## 3. 假期额度详情

查询单条假期额度账户详情，用于详情弹窗、编辑前回显、审核前查看。不写库，只读。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/leave/quota/account/detail` |
| Content-Type | `application/x-www-form-urlencoded` |
| 鉴权要求 | 需要登录（tokenID） + 数据权限范围（@ScopeAuthRequired） |

### 权限规则

| 角色 | 数据范围 |
|------|----------|
| 系统管理员 | 可查全部，操作权限全部只读（canEdit/canAudit/canReverseAudit/canDelete 均为 false） |
| HR / 部门负责人 | 只能查 `deptScopes` 范围内员工，操作权限全部只读 |
| 考勤员 | 只能查 `deptScopes` 范围内员工，拥有编辑/审核/反审核/删除操作权限 |
| 普通员工 | 不开放，直接返回无权限异常 |

### 操作权限字段规则

| 字段 | 考勤员条件 | 其他角色 |
|------|-----------|----------|
| `canEdit` | 始终为 `true` | `false` |
| `canAudit` | `auditStatus = 未审核` 时为 `true` | `false` |
| `canReverseAudit` | `auditStatus = 已审核` 时为 `true` | `false` |
| `canDelete` | `usedQuota = 0` 且 `frozenQuota = 0` 时为 `true` | `false` |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tokenID` | String | 是 | 统一鉴权令牌 |
| `quotaAccountId` | Long | 是 | 额度账户 ID |

## 5. 生成假期额度

按员工考勤档案绑定的假期制度，为权限范围内在职员工批量生成/更新年度额度账户并写入台账。只允许考勤员执行。

### 基本信息

| 项目 | 说明 |
|------|------|
| 路径 | `POST /api/leave/quota/account/generate` |
| 权限注解 | `@ScopeAuthRequired` |
| 允许角色 | 考勤员（attendanceClerk=true） |
| 事务 | `@Transactional(rollbackFor = Exception.class)` |
| 数据源 | `@DS("whd")` |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| tokenID | String | 是 | 登录令牌 |
| periodStartDate | String | 是 | 周期开始日期，格式 `yyyy-MM-dd`，后端自动推导 year 和 periodEndDate |
| year | Integer | 否 | 前端不传，后端根据 periodStartDate 自动推导 |
| periodEndDate | String | 否 | 前端不传，后端按 `periodStartDate + 1年 - 1天` 自动推导 |
| deptCodes | List\<String\> | 否 | 指定部门范围（与权限范围取交集） |
| talentCodes | List\<String\> | 否 | 指定员工范围 |
| leaveTypeCodes | List\<String\> | 否 | 仅生成这些假期类型的额度 |
| overwriteMode | String | 否 | `SKIP_EXISTING`（跳过已有）或 `DIFF_UPDATE`（差异更新），默认 `DIFF_UPDATE` |
| operatorId | Integer | 否 | 操作人 userId |
| operatorName | String | 否 | 操作人姓名，默认取当前用户 |

### 返回参数

| 字段 | 类型 | 说明 |
|------|------|------|
| success | Boolean | 是否执行成功 |
| year | Integer | 生成年度 |
| periodStartDate | String | 周期开始日期 |
| periodEndDate | String | 周期结束日期 |
| totalEmployeeCount | Integer | 命中员工数 |
| successEmployeeCount | Integer | 至少生成或更新一条额度的员工数 |
| totalAccountCount | Integer | 应处理的额度账户数 |
| createdCount | Integer | 新增账户数 |
| updatedCount | Integer | 更新账户数 |
| skippedCount | Integer | 跳过账户数 |
| ledgerCount | Integer | 写入台账数 |
| failedCount | Integer | 失败数量 |
| message | String | 结果说明 |

### 处理规则

1. **员工范围**：从 `attendance_archive`（is_deleted=0, status=1, leave_policy_code 非空）JOIN `ip_db.talent_person`（empStatus=在职），按考勤员部门权限范围过滤
2. **周期推导**：`periodEndDate = periodStartDate + 1年 - 1天`，`year = periodStartDate.getYear()`，前端不需要传 year 和 periodEndDate
3. **制度链路**：员工档案的 `leave_policy_code → attendance_leave_policy_detail`（control_quota=1, 排除 is_no_quota=1）→ `attendance_leave_quota_rule`
4. **额度计算**：以 `periodEndDate` 为截止点计算司龄/社会工龄，首年入职按在职天数折算，法定年假小数直接舍去
4. **SKIP_EXISTING**：账户已存在则跳过
5. **DIFF_UPDATE**：账户不存在则新增（versionNo=1）；已存在则重算 standardQuota，保留 usedQuota/frozenQuota，重算 actualQuota/remainQuota（versionNo+1）；无变化则跳过
6. **台账**：changeType=生成额度, changeSubType=年度生成, changeSource=额度生成接口, bizType=LEAVE_QUOTA_GENERATE

## 6. 手工维护假期额度

考勤员对未审核额度账户的手工调整，只允许维护 3 个字段：`periodStartDate`、`periodEndDate`、`adjustQuota`。已审核额度必须先反审核才能修改。

### 基本信息

| 项目 | 说明 |
|------|------|
| 路径 | `POST /api/leave/quota/account/update` |
| 权限注解 | `@ScopeAuthRequired` |
| 允许角色 | 考勤员（attendanceClerk=true） |
| 事务 | `@Transactional(rollbackFor = Exception.class)` |
| 数据源 | `@DS("whd")` |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| tokenID | String | 是 | 登录令牌 |
| quotaAccountId | Long | 是 | 额度账户 ID |
| periodStartDate | String | 否 | 周期开始日期，格式 `yyyy-MM-dd` |
| periodEndDate | String | 否 | 周期结束日期，格式 `yyyy-MM-dd`，必须大于 periodStartDate |
| adjustQuota | BigDecimal | 否 | 增减额度，允许负数（如 `-1.5` 表示减少 1.5 天） |
| versionNo | Integer | 是 | 版本号（前端从详情接口带回，乐观锁） |
| operatorId | Integer | 否 | 操作人 userId |
| operatorName | String | 否 | 操作人名称 |

> **废弃字段**：`standardQuota`、`quotaStatus`、`remark` 已废弃，传入将直接报错。

### 返回参数

| 字段 | 类型 | 说明 |
|------|------|------|
| success | Boolean | 是否成功 |
| quotaAccountId | Long | 额度账户 ID |
| talentCode | String | 员工编码 |
| leaveTypeCode | String | 假期类型编码 |
| beforeActualQuota | BigDecimal | 修改前实际额度 |
| afterActualQuota | BigDecimal | 修改后实际额度 |
| beforeRemainQuota | BigDecimal | 修改前剩余额度 |
| afterRemainQuota | BigDecimal | 修改后剩余额度 |
| versionNo | Integer | 更新后版本号 |
| message | String | 固定"手工维护成功" |

### 核心规则

1. 只允许考勤员执行
2. 已审核额度禁止修改，提示"已审核额度需先反审核后再修改"
3. 员工必须在考勤员部门权限范围内
4. `standardQuota` 和 `quotaStatus` 字段已废弃，传入直接报错
5. 至少传入一个可修改字段（`periodStartDate` / `periodEndDate` / `adjustQuota`）
6. 周期变更唯一键冲突检测：同一员工同一假期类型下，新的 `periodStartDate + periodEndDate` 组合不能与已有额度账户冲突（排除自身）
7. 后端重算公式固定：`actualQuota = standardQuota + carryoverQuota + adjustQuota`，`remainQuota = actualQuota - usedQuota - frozenQuota`
8. `remainQuota < 0` 时拒绝保存
9. 乐观锁：`versionNo` 不匹配时提示"数据可能已被他人修改"
10. 台账 `changeReason` 固定拼接本次改动内容，如："周期: 2026-01-01~2026-12-31 → 2026-02-01~2027-01-31；增减额度: 0.00 → 2.00"

### 台账规则

| 字段 | 值 |
|------|-----|
| changeType | `手工调整` |
| changeSubType | `手工维护` |
| changeSource | `人工处理` |
| bizType | `LEAVE_QUOTA_MANUAL_UPDATE` |
| bizId | null |
| bizNo | `QUOTA-MANUAL-{quotaAccountId}-{时间戳}` |
| changeReason | 拼接实际改动内容 |

## 10. 批量延期假期额度

考勤员对未审核且生效的额度账户批量延长周期结束日期，延期后写入台账。支持三种延期方式：延期到指定日期、按天延期、按月延期。支持三种目标类型：指定ID（SELECTED）、按列表条件（ALL_LIST）、按条件查询（CONDITION）。系统管理员、HR、部门负责人、普通员工都不允许执行。

### 基本信息

| 项目 | 说明 |
|------|------|
| 路径 | `POST /api/leave/quota/account/batch-extend` |
| Content-Type | `application/x-www-form-urlencoded` |
| 权限注解 | `@ScopeAuthRequired` |
| 允许角色 | 考勤员（attendanceClerk=true） |
| 事务 | `@Transactional(rollbackFor = Exception.class)` |
| 数据源 | `@DS("whd")` |

### 目标类型说明

| extendTargetType | 说明 | 数量上限 |
|------------------|------|----------|
| `SELECTED` | 指定额度账户 ID 列表（默认） | 200 |
| `ALL_LIST` | 复用额度列表分页查询条件，查询所有符合条件的额度账户 | 5000 |
| `CONDITION` | 按假期类型、周期匹配方式、员工范围条件查询 | 5000 |

| message | String | 固定"批量延期成功" |

### 核心规则

1. `extendTargetType` 不传时默认为 `SELECTED`，兼容旧版调用
2. **SELECTED 模式**：`quotaAccountIds` 必填，最多一次处理 200 条；所有 ID 必须存在且未删除，否则整体失败
3. **ALL_LIST 模式**：复用额度列表分页查询条件（不含分页参数），后端强制追加 `audit_status = '未审核' AND quota_status = '生效'`，部门范围从当前用户 `ctx.getDeptScopes()` 自动获取；最多一次处理 5000 条
4. **CONDITION 模式**：按假期类型 + 周期匹配方式 + 员工范围查询目标，后端强制追加 `audit_status = '未审核' AND quota_status = '生效'`；最多一次处理 5000 条
5. 只允许考勤员执行，`ctx.isAttendanceClerk() = true`
6. 系统管理员、HR、部门负责人、普通员工都不允许执行批量延期
7. 所有额度账户对应员工必须在当前考勤员 `ctx.getDeptScopes()` 范围内；有一个无权限，整体失败
8. 只允许延期 `quotaStatus = 生效` 的额度
9. 只允许延期 `auditStatus = 未审核` 的额度
10. `auditStatus = 已审核` 时整体失败，提示：`已审核额度需先反审核后再延期`
11. 新结束日期必须大于原 `periodEndDate`
12. 新结束日期不能小于 `periodStartDate`
13. 延期只修改 `period_end_date`，不修改额度数值（`standardQuota / carryoverQuota / adjustQuota / actualQuota / usedQuota / frozenQuota / remainQuota` 全部保持不变）
14. 修改 `period_end_date` 前检查唯一键冲突（同员工、同假期类型、同开始日期、新结束日期下已存在有效账户则整体失败）
15. 每条成功延期写一条台账
16. 任意一条更新或台账写入失败，事务整体回滚

| processMode | String | 处理方式 |
| resignDate | String | 离职日期 |
| message | String | 固定"离职额度处理成功" |

### 核心规则

1. `quotaAccountIds` 必填，最多一次处理 200 条
2. `resignDate` 必填，格式 `yyyy-MM-dd`
3. `processMode` 只允许 `INVALIDATE` 或 `PRORATE`
4. 只允许考勤员执行，`ctx.isAttendanceClerk() = true`
5. 系统管理员、HR、部门负责人、普通员工都不允许执行
6. 所有额度账户必须存在且 `is_deleted=0`；有一个不存在，整体失败
7. 所有额度账户对应员工必须在当前考勤员 `ctx.getDeptScopes()` 范围内；有一个无权限，整体失败
8. 只处理 `quotaStatus = 生效` 的额度；`失效` 或 `作废` 时整体失败
9. 只允许处理 `auditStatus = 未审核` 的额度；`已审核` 时整体失败，提示：`已审核额度需先反审核后再处理离职额度`
10. `resignDate` 必须在额度周期内：`periodStartDate <= resignDate <= periodEndDate`
11. 任意一条更新或台账写入失败，事务整体回滚

### 处理方式一：失效处理（INVALIDATE）

员工离职后，剩余额度不再可用。

**更新字段：**

| 字段 | 更新值 |
|------|--------|
| quota_status | `失效` |
| period_end_date | resignDate |
| remain_quota | `0` |
| version_no | version_no + 1 |
| remark | 离职额度失效处理：resignDate=yyyy-MM-dd，原因=xxx |
| update_time | NOW() |

standardQuota / carryoverQuota / adjustQuota / actualQuota / usedQuota / frozenQuota 全部不变。

### 处理方式二：按离职日期折算（PRORATE）

根据员工在额度周期内实际在职天数，重新折算本周期标准额度。

**计算规则：**

```
periodDays = periodStartDate 到 periodEndDate 的总天数（含首尾）
activeDays = periodStartDate 到 resignDate 的在职天数（含首尾）
ratio = activeDays / periodDays
newStandardQuota = oldStandardQuota * ratio
```

**保留字段：** carryoverQuota、adjustQuota、usedQuota、frozenQuota

**重算字段：**

```
actualQuota = newStandardQuota + carryoverQuota + adjustQuota
remainQuota = actualQuota - usedQuota - frozenQuota
```

如果 `remainQuota < 0`，整体失败，提示：`离职折算后剩余额度不能小于0，请先处理已用或冻结额度`

**更新字段：**

| 字段 | 更新值 |
|------|--------|
| standard_quota | newStandardQuota |
| actual_quota | actualQuota |
| remain_quota | remainQuota |
| period_end_date | resignDate |
| quota_status | `生效` |
| version_no | version_no + 1 |
| remark | 离职额度折算：resignDate=yyyy-MM-dd，折算比例=xx，原因=xxx |
| update_time | NOW() |

### 台账规则

| 字段 | 值 |
|------|-----|
| changeType | `离职处理` |
| changeSubType | `离职失效` 或 `离职折算` |
| changeSource | `人工处理` |
| bizType | `LEAVE_QUOTA_RESIGN_PROCESS` |
| bizId | quotaAccountId |
| bizNo | `QUOTA-RESIGN-{quotaAccountId}-{时间戳}` |
| changeQuota | afterActualQuota - beforeActualQuota |
| changeUsedQuota | `0` |

| changeReason | `离职额度处理：方式=离职失效/离职折算，离职日期=yyyy-MM-dd，原因=xxx` |

## 14. 额度后台事务分页

基于台账按 `bizType + bizNo` 聚合展示假期额度批量操作的后台事务执行记录。当前阶段只展示成功事务，不新增后台任务表。不写库，只读。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/leave/quota/task/page` |
| Content-Type | `application/x-www-form-urlencoded` |
| 鉴权要求 | 需要登录（tokenID） + 数据权限范围（@ScopeAuthRequired） |
| Controller | `LeaveQuotaTaskController`（独立，不在 LeaveQuotaAccountController 内） |

### 权限规则

| 角色 | 数据范围 |
|------|----------|
| 系统管理员 | 查询全部 |
| HR / 考勤员 / 部门负责人 | 按当前用户 `deptScopes` 过滤；前端传 `deptCode` 时与权限取交集；无 `deptScopes` 时返回空分页 |
| 普通员工 | 不开放，直接返回空分页 |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tokenID` | String | 是 | 统一鉴权令牌 |
| `bizType` | String | 否 | 业务类型，精确匹配 |
| `bizNo` | String | 否 | 业务单号，模糊查询 |
| `changeType` | String | 否 | 变更主类型，精确匹配 |
| `changeSubType` | String | 否 | 变更子类型，精确匹配 |
| `operatorName` | String | 否 | 操作人姓名，模糊查询 |
| `startTime` | String | 否 | 操作开始时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `endTime` | String | 否 | 操作结束时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `deptCode` | String | 否 | 组织编码，与当前用户权限部门取交集 |
| `pageNo` | Integer | 否 | 页码，默认 `1` |
| `pageSize` | Integer | 否 | 每页条数，默认 `20`，最大 `200` |

### 事务口径

按 `bizType + bizNo` 聚合成一条事务。适合展示的 `bizType`：

| bizType | bizTypeName |
|---------|-------------|
| `LEAVE_QUOTA_GENERATE` | 额度生成 |
| `LEAVE_QUOTA_MANUAL_UPDATE` | 手工维护 |
| `LEAVE_QUOTA_AUDIT` | 审核 |
| `LEAVE_QUOTA_REVERSE_AUDIT` | 反审核 |
| `LEAVE_QUOTA_DELETE` | 删除 |
| `LEAVE_QUOTA_BATCH_EXTEND` | 批量延期 |
| `LEAVE_QUOTA_RESIGN_PROCESS` | 离职额度处理 |

### 聚合字段

| 聚合字段 | 来源 |
|----------|------|
| taskNo | `bizNo` |
| bizType | `GROUP BY biz_type` |
| changeType | `MAX(change_type)` |
