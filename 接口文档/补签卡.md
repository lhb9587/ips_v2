## 二、补签申请初始化

`POST /api/supplement/request/self/init`

### 权限

`@ScopeAuthRequired`

### 请求参数

表单传参，不使用 `@RequestBody`。

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| talentCode | String | 否 | 指定员工编码；不传时默认当前登录员工 |
| sourceDateTime | String | 否 | 从异常入口带入的默认补签时间，格式 `yyyy-MM-dd HH:mm` |
| sourceType | String | 否 | 来源标识，如 `calendar`、`punch_record`、`missing_check` |

### 返回

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| requestNoPreview | String | 补签单号预览（不落库） |
| employee | Object | 员工信息 |
| employee.userId | Long | 用户 ID |
| employee.talentCode | String | 员工编码 |
| employee.talentName | String | 员工姓名 |
| employee.deptCode | String | 部门编码 |
| employee.deptName | String | 部门名称 |
| employee.positionId | String | 岗位 ID |
| employee.positionName | String | 岗位名称 |
| employee.empStatus | String | 用工状态 |
| supplementTypes | List | 补签卡类型（固定返回 `REPAIR_CARD/补卡`） |
| supplementTypes[].typeCode | String | 类型编码 |
| supplementTypes[].typeName | String | 类型名称 |
| supplementTypes[].sortNo | Integer | 排序 |
| supplementReasons | List | 补签卡原因（从 `attendance_supplement_reason` 查询） |
| supplementReasons[].reasonCode | String | 原因编码 |
| supplementReasons[].reasonName | String | 原因名称 |
| supplementReasons[].allowAdvance | Boolean | 是否允许提前补签 |
| supplementReasons[].sortNo | Integer | 排序 |
| defaultDetail | Object | 默认补签明细 |
| defaultDetail.attendanceDateTime | String | 默认补签时间（从 `sourceDateTime` 带入） |
| defaultDetail.remark | String | 默认备注 |
| canApply | Boolean | 是否允许申请 |
| disabledReason | String | 不允许原因（非在职/无考勤档案） |

### 业务规则

- 不传 `talentCode`：查当前登录员工；传则查指定员工并校验权限
- 权限规则：本人/管理员→通过；HR/考勤员/部门负责人→deptCode 在权限范围内→通过；其他→拒绝
- 补签类型固定返回 `REPAIR_CARD/补卡`，不查数据库
- 单号预览 `BQKD-yyyyMMdd-XXXX`，仅预览不落库
- `canApply`：非在职→false；无有效考勤档案→false

## 三、保存补签草稿

`POST /api/supplement/request/self/save`

### 权限

`@ScopeAuthRequired`

### 请求参数

表单传参，不使用 `@RequestBody`。

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| supplementRequestId | Long | 否 | 补签单业务 ID，空=新增，非空=修改 |
| talentCode | String | 否 | 员工编码，不传默认当前登录人 |
| attendanceDateTime | String | 是 | 补签时间，格式 `yyyy-MM-dd HH:mm` |
| segmentNo | Integer | 否 | 段次，默认 1 |
| reasonCode | String | 是 | 补签原因编码 |
| remark | String | 否 | 备注 |
| attachmentIds | String | 否 | 附件 ID，逗号分隔，如 `1001,1002` |
| actionType | String | 否 | 操作类型：`save`=保存草稿（默认），`submit`=保存并提交审批 |

### 返回

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| supplementRequestId | Long | 补签单业务 ID |
| requestNo | String | 补签单号 |
| status | String | 状态（`save`→`未提交`，`submit`→`审批中`） |
| saved | Boolean | 是否保存成功 |
| submitted | Boolean | 是否已提交审批（`save`→false，`submit`→true） |
| approvalInstanceId | Long | 审批实例 ID（仅 `submit` 时有值） |
| taskId | Long | 审批任务 ID（仅 `submit` 时有值） |
| talentCode | String | 员工编码 |
| talentName | String | 员工姓名 |
| attendanceDateTime | String | 补签时间 |
| reasonCode | String | 补签原因编码 |
| reasonName | String | 补签原因名称 |

### 业务规则

- 补签类型固定 `REPAIR_CARD`，前端不传；原因名称从 `attendance_supplement_reason` 查
- 校验顺序：员工在职→有效考勤档案→时间格式→原因启用→提前补签权限→重复补签
- 重复校验：同一员工同一补签时间不允许重复（修改时排除当前单据）
- 提前补签：原因 `allowAdvance=0` 时不允许补未来日期
- 新增：生成单号 `BQKD + yyyyMMddHHmmssSSS + 3位序号`，业务 ID `毫秒时间戳*1000+序号`
- 修改：只允许 `未提交`/`已退回`；已退回保存后清空 `submit_time`/`approve_time`，禁用旧审批绑定
- 修改时先逻辑删除旧明细和旧附件，再插入新的
- `actionType` 不传或 `save`：只保存草稿，不创建审批
- `actionType=submit`：先保存/修改补签单，再调用 `ApprovalWorkflowSubmitService.submit()` 提交审批中心，状态变为 `审批中`
- 提交审批由 `ApprovalWorkflowSubmitService` 统一创建审批实例、任务、审核人、动作日志，并通过 `ApprovalBusinessStatusWriteBackService` 回写业务状态为 `审批中`
- 审批中单据不允许再次 `submit`，由审批服务重复提交拦截
- 不写考勤事件、不改打卡记录、不触发计算

## 四、补签卡详情（统一详情入口）

### 权限

`@ScopeAuthRequired`（加载权限上下文用于按钮计算，查询本身不按权限范围过滤，任何已登录用户可查看）

### 请求参数

表单传参，不使用 `@RequestBody`。

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| supplementRequestId | Long | 是 | 补签单业务 ID |

### 返回

| supplementRequestId | Long | 补签单业务 ID |

| userId | Long | 用户 ID |
| deptCode | String | 部门编码 |
| deptName | String | 部门名称 |

| applyTime | String | 申请时间 |
| submitTime | String | 提交时间 |

#### 明细字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| details | List | 补签明细列表 |

| details[].segmentNo | Integer | 段次 |

| details[].effectStatus | String | 生效状态（未生效/已生效/已回滚） |

| 字段 | 类型 | 说明 |

| canReverseApprove | Boolean | 管理员/HR/考勤员 + 已通过 |

## 五、废弃/撤回补签单

`POST /api/supplement/request/self/abandon`

### 权限

无 `@ScopeAuthRequired`，只需要 token 校验。

### 请求参数

表单传参，不使用 `@RequestBody`。

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| supplementRequestId | Long | 否 | 单条补签单业务 ID |
| supplementRequestIds | String | 否 | 批量补签单业务 ID，逗号分隔，优先使用 |
| remark | String | 否 | 废弃/撤回原因 |

### 返回

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| abandoned | Boolean | 是否撤回成功 |
| successCount | Integer | 成功撤回条数 |
| supplementRequestIds | List\<Long\> | 本次撤回的补签单 ID 列表 |
| supplementRequestId | Long | 单条撤回时的补签单 ID（兼容前端） |

### 业务规则

- 只允许申请人本人操作
- 只允许 `审批中` 的补签单撤回
- 已有人审批过（同意/退回）的单据不能撤回
- `未提交` 草稿请使用删除功能
- `已退回` 补签单请编辑后重新提交
- `已通过` 补签单不允许员工端撤回
- 撤回后：补签单状态改为 `未提交`，审批实例状态改为 `已撤回`，业务绑定失效，待审批任务关闭，写入动作日志（`废弃/未提交`）
- 支持批量，最多 100 条，任意一条校验失败则整体回滚
- 不触发考勤快照事件、不改打卡记录、不触发计算

## 六、补签卡后台列表分页

`POST /api/supplement/request/admin/page`

### 权限

`@ScopeAuthRequired`

### 请求参数

表单传参，不使用 `@RequestBody`。

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 20，最大 200 |
| deptCode | String | 否 | 部门编码，传父部门会展开子部门 |
| talentCode | String | 否 | 员工编码，精确匹配 |
| talentName | String | 否 | 员工姓名，模糊查询 |
| startDate | String | 否 | 补签开始日期，格式 `yyyy-MM-dd`，按明细 `attendance_datetime` 筛选 |
| endDate | String | 否 | 补签结束日期，格式 `yyyy-MM-dd`，包含当天 |
| status | String | 否 | 单据状态：未提交/审批中/已通过/已退回/已撤回/已废弃 |
| reasonCode | String | 否 | 补签原因编码 |
| requestNo | String | 否 | 补签单号，模糊查询 |

### 返回

分页格式 `ReturnInfo.page(records, total, pageNo)`。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| supplementRequestId | Long | 补签单业务 ID |
| requestNo | String | 补签单号 |
| talentCode | String | 员工编码 |
| talentName | String | 员工姓名 |
| userId | Long | 用户 ID |
| deptCode | String | 部门编码 |
| deptName | String | 部门名称 |
| posName | String | 岗位名称 |
| attendanceDateTime | String | 第一条补签时间 |
| reasonCode | String | 原因编码 |
| reasonName | String | 原因名称 |
| supplementType | String | 补签类型（固定 `REPAIR_CARD`） |
| supplementTypeName | String | 补签类型名称（固定 `补卡`） |
| status | String | 单据状态 |
| sourceEntry | String | 来源入口 |
| applyTime | String | 申请时间 |
| submitTime | String | 提交时间 |
| approveTime | String | 通过时间 |
| approvalInstanceId | Long | 审批实例 ID |
| approvalStatus | String | 审批状态 |
| currentApproverNames | String | 当前审批人姓名，多个逗号分隔 |
| canApprove | Boolean | 当前用户可审批 |
| canReject | Boolean | 当前用户可退回 |
| canDirectPass | Boolean | 管理员/HR/考勤员可提交生效 |
| canReverseApprove | Boolean | 管理员/HR/考勤员可反审批 |
| canAbandon | Boolean | 后台固定 false |

### 业务规则

- `@ScopeAuthRequired` 加载权限上下文
- 普通员工（selfOnly）返回空列表
- 部门范围：`deptCode` 为空时使用 `deptScopes`；不为空时展开父部门子部门并与 `deptScopes` 取交集
- 系统管理员 `deptCode` 为空时不限制部门
- 日期筛选按明细 `attendance_datetime`，`endDate` 包含当天
- 排序：`submit_time DESC, create_time DESC, request_id DESC`
- 按钮权限：
  - `canApprove/canReject`：当前用户是待审批人 + 状态=审批中
  - `canDirectPass`：管理员/HR/考勤员 + 未提交/已退回
  - `canReverseApprove`：管理员/HR/考勤员 + 已通过
  - `canAbandon`：后台固定 false
