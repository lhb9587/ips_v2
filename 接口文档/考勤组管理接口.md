# 考勤组管理接口

基础路径：`/api/attendance/group`

---

## 1. G1 考勤组列表分页

`POST /api/attendance/group/page`

> 需要权限范围认证（`@ScopeAuthRequired`）。只读分页接口，不写入数据库。

### 请求

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groupCode | String | 否 | 考勤组编码，模糊查询 |
| groupName | String | 否 | 考勤组名称，模糊查询 |
| orgCode | String | 否 | 所属组织编码，精确查询 |
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 20，最大 200 |

### 请求示例

```json
{
  "groupCode": "G001",
  "groupName": "研发排班组",
  "orgCode": "100",
  "pageNo": 1,
  "pageSize": 20
}
```

### 响应

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "pageNo": 1,
    "pageSize": 20,
    "total": 1,
    "records": [
      {
        "groupId": 1001,
        "groupCode": "G001",
        "groupName": "研发排班组",
        "orgCode": "100",
        "orgName": "研发部",
        "remark": "跨组织排班",
        "memberCount": 12
      }
    ]
  }
}
```

### 查询与权限规则

- 系统管理员可查看全部考勤组
- 有部门范围时，只能查看 owner_dept_code 在 deptScopes 内的考勤组
- 普通员工/无部门范围时返回空列表
- groupCode、groupName 支持模糊查询
- orgCode 为精确查询
- orgName 由 IPS talent_organization 实时补充，不冗余存储
- memberCount 为 attendance_group_member 中 member_status='在组' 且 is_deleted=0 的成员数量
- 结果按更新时间倒序排列

## 2. G2 创建/编辑考勤组

`POST /api/attendance/group/save`

> 需要权限范围认证（`@ScopeAuthRequired`）。

### 请求

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groupId | Long | 否 | 为空=创建，非空=编辑 |
| groupCode | String | 是 | 考勤组编码，创建时必填，编辑时不可修改 |
| groupName | String | 是 | 考勤组名称 |
| orgCode | String | 是 | 所属组织编码 |
| remark | String | 否 | 备注 |
| memberTalentCodes | List\<String\> | 否 | 成员员工编码列表，传了则全量替换成员 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 请求示例

```json
{
  "groupId": 1001,
  "groupCode": "G001",
  "groupName": "研发排班组",
  "orgCode": "100",
  "remark": "跨组织排班",
  "memberTalentCodes": ["30028", "60071"],
  "operatorId": "10001",
  "operatorName": "管理员"
}
```

### 响应

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "groupId": 1001,
    "groupCode": "G001",
    "operationType": "create",
    "success": true,
    "message": "考勤组创建成功"
  }
}
```

### 校验与权限

- groupCode、groupName、orgCode 必填
- groupCode 创建后不可修改（update SQL 不包含 group_code 字段）
- groupCode 在未删除数据内唯一
- orgCode 必须在当前用户 deptScopes 内
- 系统管理员可操作全部
- 有部门范围时，只能操作范围内组织的考勤组
- 普通员工无部门范围禁止操作
- memberTalentCodes 可选，不传则不操作成员
- 传了 memberTalentCodes 时，先逻辑删除旧成员，再逐条插入新成员
- 成员可跨行政组织，但成员必须在当前用户数据权限范围内
- 成员不在权限范围时整体失败

## 3. G3 考勤组详情+成员列表

`POST /api/attendance/group/detail`

> 需要权限范围认证（`@ScopeAuthRequired`）。只读接口，查询考勤组详情及成员分页列表。

### 请求

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groupId | Long | 是 | 考勤组ID |
| memberKeyword | String | 否 | 成员关键字，匹配员工编码或姓名 |
| pageNo | Integer | 否 | 成员列表页码，默认 1 |
| pageSize | Integer | 否 | 成员列表每页条数，默认 20，最大 200 |

### 请求示例

```json
{
  "groupId": 1001,
  "memberKeyword": "张",
  "pageNo": 1,
  "pageSize": 20
}
```

### 响应

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "groupId": 1001,
    "groupCode": "G001",
    "groupName": "研发排班组",
    "orgCode": "100",
    "orgName": "研发部",
    "remark": "跨组织排班",
    "members": {
      "pageNo": 1,
      "pageSize": 20,
      "total": 1,
      "records": [
        {
          "talentCode": "30028",
          "talentName": "张三",
          "posId": "5",
          "posName": null,
          "deptCode": "100",
          "deptName": "研发部",
          "transferOutTime": null,
          "transferOutOrg": null
        }
      ]
    }
  }
}
```

### 查询与权限规则

- groupId 必填，不存在时抛出异常
- 系统管理员可查看全部考勤组
- 有部门范围时，只能查看 owner_dept_code 在 deptScopes 内的考勤组
- 普通员工无部门范围时禁止查看
- 成员列表只展示 member_status='在组' 且 is_deleted=0 的成员
- memberKeyword 同时匹配 talentCode 和 IPS talentName（不区分大小写）
- orgName、talentName、deptName 等由 IPS talent_person/talent_organization 实时补充
- 成员采用内存分页（先查全部成员，过滤后再分页）

## 4. G4 成员维护（整体替换）

`POST /api/attendance/group/member/save`

> 需要权限范围认证（`@ScopeAuthRequired`）。事务操作，先逻辑删除旧成员再插入新成员。

### 请求

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groupId | Long | 是 | 考勤组ID |
| memberTalentCodes | List\<String\> | 否 | 成员员工编码列表，全量替换；空列表=清空成员；null=清空成员 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 请求示例

```json
{
  "groupId": 1001,
  "memberTalentCodes": ["30028", "60071"],
  "operatorId": "10001",
  "operatorName": "管理员"
}
```

### 响应

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "groupId": 1001,
    "memberCount": 2,
    "success": true,
    "message": "成员保存成功"
  }
}
```

### 校验与权限

- groupId 必填，考勤组必须存在且未删除
- 系统管理员可操作全部考勤组成员
- 有部门范围时，只能操作 owner_dept_code 在 deptScopes 内的考勤组
- 普通员工无部门范围禁止操作
- 所有成员必须存在于 IPS 系统
- 所有成员必须在当前用户数据权限范围内（成员所属 deptCode 在 deptScopes 内）
- 成员编码列表内不可重复
- 整体替换：先逻辑删除旧成员（is_deleted=1），再逐条插入新成员（member_status='在组'）
- 事务内完成，任一步骤失败全部回滚

## 5. G5 删除前引用校验

`POST /api/attendance/group/delete-check`

> 需要权限范围认证（`@ScopeAuthRequired`）。只读接口，检查考勤组是否可被删除。

### 请求

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groupId | Long | 是 | 考勤组ID |

### 请求示例

```json
{
  "groupId": 1001
}
```

### 响应

无引用时：

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "canDelete": true,
    "reason": null,
    "referenceCount": 0
  }
}
```

有引用时：

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "canDelete": false,
    "reason": "该考勤组已被排班引用，不允许删除",
    "referenceCount": 3
  }
}
```

### 校验与权限

- groupId 必填，考勤组不存在时抛出异常
- 系统管理员不允许删除（只读角色）
- 有部门范围的考勤员可校验权限范围内的考勤组
- 引用来源：attendance_schedule_day（排班日表），检查 group_id 关联且 is_deleted=0 的记录数
- 后续可扩展更多引用来源（排班任务表、规则表等）

## 6. G6 删除考勤组

`POST /api/attendance/group/delete`

> 需要权限范围认证（`@ScopeAuthRequired`）。事务操作，删除前会再次执行引用校验。

### 请求

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groupId | Long | 是 | 考勤组ID |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 请求示例

```json
{
  "groupId": 1001,
  "operatorId": "90001",
  "operatorName": "考勤员"
}
```

### 响应

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": null
}
```

### 校验与权限

- groupId 必填，考勤组不存在时抛出异常
- 系统管理员不允许删除（只读角色）
- 有部门范围的考勤员可删除权限范围内的考勤组
- 普通员工无部门范围禁止操作
- 删除前再次执行引用校验（不依赖前端先调 delete-check），有排班引用时抛出异常
- 逻辑删除考勤组主表（is_deleted=1）
- 逻辑删除成员关系（is_deleted=1），方便追溯
- 事务内完成，删除主表和成员关系原子操作
