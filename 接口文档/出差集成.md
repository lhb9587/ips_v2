## 1. 出差变更通知

`POST /api/integration/business-trip/change-notify`

### 作用

IPS 出差模块在出差新增/修改/删除后调用本接口，考勤系统将受影响日期区间标记为"待计算"。不触发重算，不碰审批中心。

按 changeType 区分处理：
- **ADD** — 只标记新区间（`userId` + `startDate` ~ `endDate`）
- **UPDATE** — 标记旧区间（`oldUserId` + `oldStartDate` ~ `oldEndDate`）+ 新区间（`userId` + `startDate` ~ `endDate`）
- **DELETE** — 只标记旧区间（`oldUserId` + `oldStartDate` ~ `oldEndDate`）

### 请求参数

| 字段 | 必填 | 说明 |
|------|------|------|
| btId | 否 | 出差单 ID，用于日志追溯 |
| userId | ADD/UPDATE 必填，DELETE 兼容字段 | 员工用户 ID |
| startDate | ADD/UPDATE 必填，DELETE 兼容字段 | 受影响开始日期，格式 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss` |
| endDate | ADD/UPDATE 必填，DELETE 兼容字段 | 受影响结束日期，格式 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss` |
| changeType | 是 | 变更类型：`ADD` / `UPDATE` / `DELETE` |
| oldUserId | UPDATE/DELETE 推荐 | 修改/删除前员工用户 ID，为空时使用 `userId` |
| oldStartDate | UPDATE/DELETE 推荐 | 修改/删除前开始日期，为空时使用 `startDate` |
| oldEndDate | UPDATE/DELETE 推荐 | 修改/删除前结束日期，为空时使用 `endDate` |

> **重要**：UPDATE/DELETE 如果不传 `oldStartDate`/`oldEndDate`，可能无法清理旧日期上的出差影响。IPS 应在修改/删除出差单前记录旧值并传入。如果旧区间与新区间相同（相同 userId + 相同日期），会自动去重。

### 请求示例

ADD（新增出差）：

```json
{
  "btId": 12345,
  "userId": 1001,
  "startDate": "2026-06-10",
  "endDate": "2026-06-12",
  "changeType": "ADD"
}
```

UPDATE（修改出差，含旧区间）：

```json
{
  "btId": 12345,
  "userId": 1001,
  "startDate": "2026-06-15",
  "endDate": "2026-06-18",
  "changeType": "UPDATE",
  "oldUserId": 1001,
  "oldStartDate": "2026-06-10",
  "oldEndDate": "2026-06-12"
}
```

DELETE（删除出差，推荐只传旧范围）：

```json
{
  "btId": 12345,
  "changeType": "DELETE",
  "oldUserId": 1001,
  "oldStartDate": "2026-06-10",
  "oldEndDate": "2026-06-12"
}
```

> DELETE 推荐只传 `oldUserId`、`oldStartDate`、`oldEndDate`；`userId`、`startDate`、`endDate` 仅用于兼容旧调用。

### 返回字段

| 字段 | 说明 |
|------|------|
| talentCode | 员工编码（兼容：第一个区间的 talentCode） |
| pendingFromDate | 待计算开始日期（兼容：第一个区间的 fromDate） |
| pendingToDate | 待计算结束日期（兼容：第一个区间的 toDate） |
| affectedPeriods | 所有受影响的考勤周期列表（并集），如 `["202605", "202606"]` |
| pendingRanges | 所有待计算区间明细列表 |

**pendingRanges 子项：**

| 字段 | 说明 |
|------|------|
| talentCode | 该区间的员工编码 |
| fromDate | 该区间开始日期 |
| toDate | 该区间结束日期 |
| affectedPeriods | 该区间受影响的考勤周期列表 |

### 成功示例

ADD 返回单个区间：

```json
{
  "success": true,
  "data": {
    "talentCode": "11318",
    "pendingFromDate": "2026-06-10",
    "pendingToDate": "2026-06-12",
    "affectedPeriods": ["202606"],
    "pendingRanges": [
      {
        "talentCode": "11318",
        "fromDate": "2026-06-10",
        "toDate": "2026-06-12",
        "affectedPeriods": ["202606"]
      }
    ]
  },
  "message": "ok",
  "messageType": 0
}
```

UPDATE 返回两个区间（旧 + 新）：

```json
{
  "success": true,
  "data": {
    "talentCode": "11318",
    "pendingFromDate": "2026-06-01",
    "pendingToDate": "2026-06-03",
    "affectedPeriods": ["202606"],
    "pendingRanges": [
      {
        "talentCode": "11318",
        "fromDate": "2026-06-01",
        "toDate": "2026-06-03",
        "affectedPeriods": ["202606"]
      },
      {
        "talentCode": "11318",
        "fromDate": "2026-06-15",
        "toDate": "2026-06-18",
        "affectedPeriods": ["202606"]
      }
    ]
  },
  "message": "ok",
  "messageType": 0
}
```

### 处理规则

1. **参数校验**：`changeType` 必填；ADD/UPDATE 要求 `userId`、`startDate`、`endDate`；DELETE 要求传旧范围（`oldUserId/oldStartDate/oldEndDate`）或兼容传 `userId/startDate/endDate`。
2. **changeType**：只允许 `ADD`、`UPDATE`、`DELETE`（不区分大小写）。
3. **日期格式**：支持 `yyyy-MM-dd` 和 `yyyy-MM-dd HH:mm:ss`，带时间部分时只取日期。`endDate` 不能小于 `startDate`。
4. **员工校验**：根据 `userId`（和 `oldUserId`）查询 `ip_db.talent_person`，不存在则报错。
5. **多区间标记**：
   - ADD：只标记 `userId` 的 `startDate` ~ `endDate`
   - UPDATE：标记旧区间 + 新区间；旧区间与新区间相同时去重
   - DELETE：只标记 `oldUserId` 的 `oldStartDate` ~ `oldEndDate`
6. **跨周期拆分**：调用 `AttendanceCalcCycleStateTransitionService.markPendingRange`，跨周期自动拆分。
7. **幂等性**：同一员工同一周期多次通知，dirty range 会自动合并（取最小 fromDate、最大 toDate），不会重复创建。
8. **不触发重算**：仅标记状态，不调用考勤计算服务。
9. **独立 Mapper**：使用 `BusinessTripChangeNotifyMapper`，不依赖补签模块 Mapper。
