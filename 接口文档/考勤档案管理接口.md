# 考勤档案管理接口

基础路径：`/api/attendance/archive`

统一返回结构：`ReturnInfo<T>`

公共规则：
- Content-Type：`application/x-www-form-urlencoded`，参数通过表单提交
- tokenID 通过 query 参数传递，如 `?tokenID=xxx`
- 标注 `@ScopeAuthRequired` 的接口需要加载用户权限范围

---

## 1. A5-02创建考勤档案

`POST /api/attendance/archive/create`

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| talentCode | String | 是 | 员工编码 |
| attendanceNo | String | 是 | 考勤编号，需与考勤机编码一致；当前创建接口不会自动默认成员工编码 |
| attendanceOrgCode | String | 否 | 考勤组织编码 |
| attendancePolicyCode | String | 是 | 考勤制度编码；当前创建接口不会自动读取组织默认配置 |
| leavePolicyCode | String | 是 | 假期制度编码；当前创建接口不会自动读取组织默认配置 |
| defaultShiftCode | String | 是 | 默认班次编码；当前创建接口不会自动读取组织默认配置 |
| isPunchAttendance | Integer | 否 | 是否打卡考勤（0否/1是），不传默认 1 |
| isAutoSchedule | Integer | 否 | 是否自动排班（0否/1是），不传默认 1 |
| scheduleMode | String | 否 | 排班模式（fixed固定/rotation轮班），不传默认 fixed |
| rotationRuleCode | String | 否 | 轮班规则编码，scheduleMode=rotation时需填 |
| rotationEffectiveDate | LocalDate | 否 | 轮班生效日期 |
| rotationAnchorDate | LocalDate | 否 | 轮班锚点日期 |
| rotationStartSeq | Integer | 否 | 锚点日期对应明细序号，不传默认 1 |
| entryDate | LocalDate | 否 | 入职日期 |
| regularDate | LocalDate | 否 | 转正日期 |
| resignDate | LocalDate | 否 | 离职日期 |
| remark | String | 否 | 备注 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 响应

```json
{
  "success": true,
  "data": {
    "archiveId": 1747800001,
    "talentCode": "30028",
    "operationType": "create",
    "success": true,
    "message": "创建成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验规则

- talentCode 必填且同一员工不允许重复创建
- attendanceNo 必填且不允许与已有未删除档案重复
- attendancePolicyCode 必填
- leavePolicyCode 必填
- defaultShiftCode 必填
- 创建接口当前不会按 attendanceOrgCode 自动带出组织默认考勤制度、假期制度、默认班次

### 默认值

| 字段 | 默认值 | 说明 |
|------|------|------|
| archiveId | 后端自动生成 | 使用雪花 ID |
| isPunchAttendance | 1 | 默认打卡考勤 |
| isAutoSchedule | 1 | 默认自动排班 |
| scheduleMode | fixed | 默认固定班次 |
| rotationStartSeq | 1 | 默认轮班明细序号从 1 开始 |
| status | 1 | 默认启用 |
| isDeleted | 0 | 默认未删除 |
| createTime / updateTime | 数据库自动维护 | 创建时由数据库默认值维护 |

### 可为空字段

- attendanceOrgCode
- rotationRuleCode
- rotationEffectiveDate
- rotationAnchorDate
- entryDate
- regularDate
- resignDate
- remark
- operatorId
- operatorName

## 2. A5-02编辑考勤档案

`POST /api/attendance/archive/update`

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveId | Long | 推荐 | 档案主键，优先定位 |
| talentCode | String | 备选 | 员工编码，archiveId 为空时按此定位 |
| processMode | String | 否 | 处理方式：`correct`（纠正）/ `change`（变更），不传默认 `correct` |
| effectiveDate | LocalDate | change 必填 | 版本生效日期，`processMode=change` 时必填，`processMode=correct` 时忽略 |
| defaultShiftCode | String | 否 | 默认班次编码，correct 和 change 均可修改 |
| isPunchAttendance | Integer | 否 | 是否打卡考勤（0否/1是），correct 和 change 均可修改 |
| isAutoSchedule | Integer | 否 | 是否自动排班（0否/1是），correct 和 change 均可修改 |
| remark | String | 否 | 备注 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 响应

```json
{
  "success": true,
  "data": {
    "archiveId": 1747800001,
    "talentCode": "30028",
    "operationType": "update",
    "processMode": "correct",
    "success": true,
    "message": "考勤档案纠正成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 两种编辑模式

#### correct 模式（默认）

- 更新 `attendance_archive` 主表
- 同步当前生效版本（`attendance_archive_version`）的 `defaultShiftCode`/`isPunchAttendance`/`isAutoSchedule`
- **不写** `attendance_archive_history`
- **不新增** `attendance_archive_version`

#### change 模式

- 只允许修改 3 个字段：`isPunchAttendance`、`defaultShiftCode`、`isAutoSchedule`
- 更新 `attendance_archive` 主表（其余字段沿用修改前值）
- 写 `attendance_archive_history`
- 当前生效版本 → `expired`（`expireDate = effectiveDate - 1天`）
- 新增一条 `effective` 版本（`effectiveDate = request.effectiveDate`，`expireDate = 2099-12-31`）

### 校验规则

- archiveId 或 talentCode 必须能定位到一条未删除档案
- `processMode` 只能为 `correct` 或 `change`
- `processMode=change` 时 `effectiveDate` 必填
- `processMode=change` 时禁止传入以下字段（传入则报错）：
  - `attendancePolicyCode`、`leavePolicyCode`、`attendanceOrgCode`
  - `scheduleMode`、`rotationRuleCode`、`rotationEffectiveDate`、`rotationAnchorDate`、`rotationStartSeq`
  - `entryDate`、`regularDate`、`resignDate`
- `attendancePolicyCode` / `leavePolicyCode` 在编辑接口中**永远不允许修改**，即使 correct 模式传入也会被强制沿用旧值

## 3. A5-05 启用/禁用考勤档案

`POST /api/attendance/archive/change-status`

接口标注 `@ScopeAuthRequired`。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveId | Long | 推荐 | 档案主键，优先定位 |
| talentCode | String | 备选 | 员工编码，archiveId 为空时按此定位 |
| status | Integer | 是 | 目标状态（0禁用/1启用） |
| operatorId | String | 否 | 操作人ID，用于历史记录 |
| operatorName | String | 否 | 操作人姓名，用于历史记录 |
| remark | String | 否 | 操作备注；未传时按启用/禁用自动写入默认备注 |

### 响应

| 字段 | 类型 | 说明 |
|------|------|------|
| archiveId | Long | 档案主键 |
| talentCode | String | 员工编码 |
| operationType | String | 操作类型：enable/disable |
| status | Integer | 切换后的状态 |
| success | boolean | 是否操作成功 |
| message | String | 结果说明 |
| disableDate | String | 禁用日期，格式 yyyy-MM-dd；启用时为 null |
| deletedScheduleCount | Integer | 禁用时删除的排班记录数量；启用时为 0 |

### 禁用响应示例

```json
{
  "success": true,
  "data": {
    "archiveId": 5,
    "talentCode": "10030",
    "operationType": "disable",
    "status": 0,
    "success": true,
    "message": "考勤档案禁用成功",
    "disableDate": "2026-05-15",
    "deletedScheduleCount": 12
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 启用响应示例

```json
{
  "success": true,
  "data": {
    "archiveId": 5,
    "talentCode": "10030",
    "operationType": "enable",
    "status": 1,
    "success": true,
    "message": "考勤档案启用成功",
    "disableDate": null,
    "deletedScheduleCount": 0
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验与历史

- archiveId 或 talentCode 必须能定位到一条未删除档案
- status 只能为 0 或 1，目标状态与当前状态一致时返回业务错误
- 状态更新成功后写入 `attendance_archive_history`，`change_type` 为 `enable` 或 `disable`
- 历史记录会保存变更前后档案快照、操作人和备注

### 禁用联动

- 禁用成功后，逻辑删除该员工**禁用日期当天及以后**的排班记录
- 禁用日期取后端当前日期（`LocalDate.now()`）
- 历史日期排班不删除
- 删除排班数量通过 `deletedScheduleCount` 返回
- 禁用后该员工不进入自动排班范围（轮班、默认班次自动排班均过滤 `status=1`）
- 整体在同一事务中：档案状态更新失败不删排班，删排班失败全部回滚

### 启用规则

- 启用只改档案状态和写历史，不自动补生成排班
- 启用后需手动排班或等自动排班任务触发

## 4. A5-06 删除考勤档案

`POST /api/attendance/archive/delete`

### 请求参数参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveId | Long | 是 | 档案主键 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 响应

```json
{
  "success": true,
  "data": {
    "archiveId": 1747800001,
    "talentCode": "30028",
    "operationType": "delete",
    "success": true,
    "message": "考勤档案删除成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验规则

- archiveId 必填，必须能定位到一条未删除档案
- 员工在以下任一表中存在数据时阻止删除：`attendance_schedule_day`、`attendance_punch_record`、`attendance_result_day_detail`、`attendance_result_period_summary`、`attendance_leave_request`、`attendance_overtime_request`、`attendance_supplement_request`
- 错误提示：`该员工已有考勤业务数据，不允许删除档案`
- 逻辑删除（`is_deleted=1`），不物理删除
- 删除成功后写入 `attendance_archive_history`，`change_type` 为 `delete`

## 6. A5-10 批量赋值考勤档案

`POST /api/attendance/archive/batch-assign`

> 最小实现只支持已建档员工批量更新核心字段，不做导入、不做预览。

### 请求参数参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveIds | List<Long> | 二选一 | 档案主键列表，最多 200 条，不允许重复。与 talentCodes 二选一 |
| talentCodes | List<String> | 二选一 | 员工编码列表，最多 200 条，不允许重复。员工必须已建档。与 archiveIds 二选一 |
| attendancePolicyCode | String | 否 | 考勤制度编码 |
| leavePolicyCode | String | 否 | 假期制度编码 |
| defaultShiftCode | String | 否 | 默认班次编码 |
| isPunchAttendance | Integer | 否 | 是否打卡考勤（0否/1是） |
| isAutoSchedule | Integer | 否 | 是否自动排班（0否/1是），不传保持原值 |
| scheduleMode | String | 否 | 排班模式（fixed固定/rotation轮班） |
| rotationRuleCode | String | 否 | 轮班规则编码 |
| rotationEffectiveDate | LocalDate | 否 | 轮班规则生效日期 |
| rotationAnchorDate | LocalDate | 否 | 轮班锚点日期 |
| rotationStartSeq | Integer | 否 | 锚点日期对应明细序号 |
| operatorId | String | 否 | 操作人ID，用于历史记录 |
| operatorName | String | 否 | 操作人姓名，用于历史记录 |

### 请求参数示例

```
Content-Type: application/x-www-form-urlencoded

archiveIds=1001&archiveIds=1002&attendancePolicyCode=001&leavePolicyCode=JQZD001&defaultShiftCode=001&isAutoSchedule=1&operatorId=10001&operatorName=管理员
```

按员工编码调用：

```
talentCodes=10465&talentCodes=30028&attendancePolicyCode=001&defaultShiftCode=001&operatorId=10001&operatorName=管理员
```

> archiveIds 和 talentCodes 二选一，不能同时传。列表类型参数通过同名参数多次传递。

### 响应

```json
{
  "success": true,
  "data": {
    "operationType": "batch_assign",
    "totalCount": 2,
    "successCount": 2,
    "success": true,
    "message": "考勤档案批量赋值成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验与权限

- `archiveIds` 必填，最多 200 条，不允许重复或空值
- 至少传一个要修改的字段
- 只更新未删除档案
- 系统管理员可改全部
- 有部门范围时，只能修改 `attendance_org_code` 在 `deptScopes` 内的档案
- 普通员工不允许批量赋值
- 部分档案不存在、已删除或无权限时整体失败，不做半成功
- 每条档案更新前读取旧值，更新后逐条写入 `attendance_archive_history`
- 历史记录 `change_type=batch_assign`，`change_mode=batch`

### 校验与权限

- 系统管理员可给全部员工建档
- 有部门范围时，只能给 deptScopes 内员工建档
- 普通员工/无部门范围时禁止操作
- 员工必须存在于 IPS（ip_db.talent_person），不存在则整体失败
- 员工必须在 attendance_archive 中无未删除档案（is_deleted=0），已建档则整体失败
- 员工所属组织必须有默认配置（attendance_org_default_config），且 attendancePolicyCode、leavePolicyCode、defaultShiftCode 均不能为空，否则整体失败

### 历史记录

- 每创建一条档案，写一条 attendance_archive_history
- change_type = batch_create_by_default，change_mode = batch
- before_snapshot = null，after_snapshot = 创建后的档案 JSON

### 查询与权限规则

- archiveId 或 talentCode 至少传一个，否则返回参数错误
- archiveId 优先；未传 archiveId 时按 talentCode 查询对应档案
- 档案不存在时返回业务异常：考勤档案不存在
- 系统管理员可查看全部版本记录
- 有部门范围时，只能查看 attendance_org_code 在范围内的档案版本
- 普通员工只能查看本人档案版本
- 越权返回业务异常：无权查看该考勤档案版本
- 按生效日期倒序、ID 倒序排列

### 版本生命周期说明

| 操作 | changeMode | 对版本表的影响 |
|------|-----------|---------------|
| 创建档案 | create | 新增一条 version_status=effective 的版本（expireDate=2099-12-31） |
| 编辑（correct） | correct | 直接修改当前生效版本的 defaultShiftCode/isPunchAttendance/isAutoSchedule，不新增版本，不写历史 |
| 编辑（change） | change | 当前生效版本 → expired（expireDate=新版本生效日前一天），新增一条 effective 版本 |
| 禁用档案 | disable | 不修改版本表，仅更新档案状态和删除排班 |
| 启用档案 | enable | 新增一条 version_status=effective 的版本（effectiveDate=启用当日，expireDate=2099-12-31） |

> **版本操作维度**：所有版本变更（查/过期/禁用）均按 `archiveId` 操作，不按 `talentCode`，避免同一员工历史多档案误伤。

### A5-02 创建/编辑接口变更

创建接口新增 `effectiveDate` 请求参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| effectiveDate | LocalDate | 否 | 版本生效日期；创建时不传默认当天 |

编辑接口新增 `processMode` 和 `effectiveDate` 请求参数（详见 A5-02 编辑接口文档）。

### A5-05 启用/禁用接口版本联动

- 禁用：不修改版本表，仅更新档案状态、删除排班、写历史
- 启用：新增一条 version_status=effective 的版本，effectiveDate 为启用当日，expireDate=2099-12-31

### 数据来源与名称补充

- 版本 code 字段（`attendancePolicyCode`、`leavePolicyCode`、`defaultShiftCode` 等）**以版本表为准**，不用主表当前值覆盖历史值
- 名称字段（`talentName`、`attendanceOrgName`、`attendancePolicyName`、`leavePolicyName`、`defaultShiftName`）通过 LEFT JOIN 实时补充，仅作展示用途
- 名称来源：`ip_db.talent_person`、`ip_db.talent_organization`、`attendance_policy`、`attendance_leave_policy`、`attendance_shift_dict`
- 日期字段（`effectiveDate`、`expireDate`、`createTime`）在 SQL 中格式化为字符串直接返回，不做 Jackson Date 序列化
