# 考勤档案管理接口

基础路径：`/api/attendance/archive`

统一返回结构：`ReturnInfo<T>`

公共规则：
- Content-Type：`application/x-www-form-urlencoded`，参数通过表单提交
- tokenID 通过 query 参数传递，如 `?tokenID=xxx`
- 标注 `@ScopeAuthRequired` 的接口需要加载用户权限范围

---

## 1. A5-02创建考勤档案

`POST /api/attendance/archive/create`

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| talentCode | String | 是 | 员工编码 |
| attendanceNo | String | 是 | 考勤编号，需与考勤机编码一致；当前创建接口不会自动默认成员工编码 |
| attendanceOrgCode | String | 否 | 考勤组织编码 |
| attendancePolicyCode | String | 是 | 考勤制度编码；当前创建接口不会自动读取组织默认配置 |
| leavePolicyCode | String | 是 | 假期制度编码；当前创建接口不会自动读取组织默认配置 |
| defaultShiftCode | String | 是 | 默认班次编码；当前创建接口不会自动读取组织默认配置 |
| isPunchAttendance | Integer | 否 | 是否打卡考勤（0否/1是），不传默认 1 |
| isAutoSchedule | Integer | 否 | 是否自动排班（0否/1是），不传默认 1 |
| scheduleMode | String | 否 | 排班模式（fixed固定/rotation轮班），不传默认 fixed |
| rotationRuleCode | String | 否 | 轮班规则编码，scheduleMode=rotation时需填 |
| rotationEffectiveDate | LocalDate | 否 | 轮班生效日期 |
| rotationAnchorDate | LocalDate | 否 | 轮班锚点日期 |
| rotationStartSeq | Integer | 否 | 锚点日期对应明细序号，不传默认 1 |
| entryDate | LocalDate | 否 | 入职日期 |
| regularDate | LocalDate | 否 | 转正日期 |
| resignDate | LocalDate | 否 | 离职日期 |
| remark | String | 否 | 备注 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 响应

```json
{
  "success": true,
  "data": {
    "archiveId": 1747800001,
    "talentCode": "30028",
    "operationType": "create",
    "success": true,
    "message": "创建成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验规则

- talentCode 必填且同一员工不允许重复创建
- attendanceNo 必填且不允许与已有未删除档案重复
- attendancePolicyCode 必填
- leavePolicyCode 必填
- defaultShiftCode 必填
- 创建接口当前不会按 attendanceOrgCode 自动带出组织默认考勤制度、假期制度、默认班次

### 默认值

| 字段 | 默认值 | 说明 |
|------|------|------|
| archiveId | 后端自动生成 | 使用雪花 ID |
| isPunchAttendance | 1 | 默认打卡考勤 |
| isAutoSchedule | 1 | 默认自动排班 |
| scheduleMode | fixed | 默认固定班次 |
| rotationStartSeq | 1 | 默认轮班明细序号从 1 开始 |
| status | 1 | 默认启用 |
| isDeleted | 0 | 默认未删除 |
| createTime / updateTime | 数据库自动维护 | 创建时由数据库默认值维护 |

### 可为空字段

- attendanceOrgCode
- rotationRuleCode
- rotationEffectiveDate
- rotationAnchorDate
- entryDate
- regularDate
- resignDate
- remark
- operatorId
- operatorName

## 2. A5-02编辑考勤档案

`POST /api/attendance/archive/update`

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveId | Long | 推荐 | 档案主键，优先定位 |
| talentCode | String | 备选 | 员工编码，archiveId 为空时按此定位 |
| 其余字段 | - | 否 | 同创建接口，只更新传入的字段 |

### 响应

同创建接口，`operationType` 为 `"update"`。

### 校验规则

- archiveId 或 talentCode 必须能定位到一条未删除档案
- attendanceNo 如修改则不允许与已有档案重复

## 3. A5-05 启用/禁用考勤档案

`POST /api/attendance/archive/change-status`

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveId | Long | 推荐 | 档案主键，优先定位 |
| talentCode | String | 备选 | 员工编码，archiveId 为空时按此定位 |
| status | Integer | 是 | 目标状态（0禁用/1启用） |
| operatorId | String | 否 | 操作人ID，用于历史记录 |
| operatorName | String | 否 | 操作人姓名，用于历史记录 |
| remark | String | 否 | 操作备注；未传时按启用/禁用自动写入默认备注 |

### 响应

```json
{
  "success": true,
  "data": {
    "archiveId": 1747800001,
    "talentCode": "30028",
    "operationType": "disable",
    "status": 0,
    "success": true,
    "message": "考勤档案禁用成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验与历史

- archiveId 或 talentCode 必须能定位到一条未删除档案
- status 只能为 0 或 1，目标状态与当前状态一致时返回业务错误
- 状态更新成功后写入 `attendance_archive_history`，`change_type` 为 `enable` 或 `disable`
- 历史记录会保存变更前后档案快照、操作人和备注

## 4. A5-06 删除考勤档案

`POST /api/attendance/archive/delete`

### 请求参数参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveId | Long | 是 | 档案主键 |
| operatorId | String | 否 | 操作人ID |
| operatorName | String | 否 | 操作人姓名 |

### 响应

```json
{
  "success": true,
  "data": {
    "archiveId": 1747800001,
    "talentCode": "30028",
    "operationType": "delete",
    "success": true,
    "message": "考勤档案删除成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验规则

- archiveId 必填，必须能定位到一条未删除档案
- 员工在以下任一表中存在数据时阻止删除：`attendance_schedule_day`、`attendance_punch_record`、`attendance_result_day_detail`、`attendance_result_period_summary`、`attendance_leave_request`、`attendance_overtime_request`、`attendance_supplement_request`
- 错误提示：`该员工已有考勤业务数据，不允许删除档案`
- 逻辑删除（`is_deleted=1`），不物理删除
- 删除成功后写入 `attendance_archive_history`，`change_type` 为 `delete`

## 5. A5-07 查询未建档员工

`POST /api/attendance/archive/unarchived/page`

> 只读分页接口，不写入数据库。

### 请求参数参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 20，最大 200 |
| talentCode | String | 否 | 员工编码，模糊查询 |
| talentName | String | 否 | 员工姓名，模糊查询 |
| deptCode | String | 否 | 组织编码 |
| empStatus | String | 否 | 用工状态 |

### 响应

```json
{
  "success": true,
  "data": [
    {
      "talentCode": "30028",
      "talentName": "张三",
      "deptCode": "100",
      "deptName": "技术部",
      "posId": "5",
      "empStatus": "在职",
      "joinDate": "2020-01-01",
      "defaultAttendancePolicyCode": "P001",
      "defaultLeavePolicyCode": "L001",
      "defaultShiftCode": "S001",
      "configComplete": true
    }
  ],
  "total": 1,
  "currPage": 1,
  "message": "ok",
  "messageType": 0
}
```

### 查询规则

- 系统管理员查询全部未建档员工
- 有部门范围时，只查询 `deptScopes` 内员工
- 普通员工无部门范围时返回空列表
- 员工来源为 `ip_db.talent_person`，组织名称来源为 `ip_db.talent_organization`
- 通过 `whd_attendance.attendance_archive` 排除 `is_deleted=0` 的已有档案员工
- 组织默认配置来源为 `attendance_org_default_config`

## 6. A5-10 批量赋值考勤档案

`POST /api/attendance/archive/batch-assign`

> 最小实现只支持已建档员工批量更新核心字段，不做导入、不做预览。

### 请求参数参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archiveIds | List<Long> | 是 | 档案主键列表，最多 200 条，不允许重复 |
| attendancePolicyCode | String | 否 | 考勤制度编码 |
| leavePolicyCode | String | 否 | 假期制度编码 |
| defaultShiftCode | String | 否 | 默认班次编码 |
| isPunchAttendance | Integer | 否 | 是否打卡考勤（0否/1是） |
| isAutoSchedule | Integer | 否 | 是否自动排班（0否/1是），不传保持原值 |
| scheduleMode | String | 否 | 排班模式（fixed固定/rotation轮班） |
| rotationRuleCode | String | 否 | 轮班规则编码 |
| rotationEffectiveDate | LocalDate | 否 | 轮班规则生效日期 |
| rotationAnchorDate | LocalDate | 否 | 轮班锚点日期 |
| rotationStartSeq | Integer | 否 | 锚点日期对应明细序号 |
| operatorId | String | 否 | 操作人ID，用于历史记录 |
| operatorName | String | 否 | 操作人姓名，用于历史记录 |

### 请求参数示例

```
Content-Type: application/x-www-form-urlencoded

archiveIds=1001&archiveIds=1002&attendancePolicyCode=001&leavePolicyCode=JQZD001&defaultShiftCode=001&isAutoSchedule=1&operatorId=10001&operatorName=管理员
```

> 列表类型参数通过同名参数多次传递，如 `archiveIds=1001&archiveIds=1002`。

### 响应

```json
{
  "success": true,
  "data": {
    "operationType": "batch_assign",
    "totalCount": 2,
    "successCount": 2,
    "success": true,
    "message": "考勤档案批量赋值成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验与权限

- `archiveIds` 必填，最多 200 条，不允许重复或空值
- 至少传一个要修改的字段
- 只更新未删除档案
- 系统管理员可改全部
- 有部门范围时，只能修改 `attendance_org_code` 在 `deptScopes` 内的档案
- 普通员工不允许批量赋值
- 部分档案不存在、已删除或无权限时整体失败，不做半成功
- 每条档案更新前读取旧值，更新后逐条写入 `attendance_archive_history`
- 历史记录 `change_type=batch_assign`，`change_mode=batch`

## 9. A5-08 未建档批量建档

`POST /api/attendance/archive/batch-create-by-default`

> 按员工所属组织的默认配置批量创建考勤档案，不做导入、不做预览、不做部分成功。

### 请求参数参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| talentCodes | List\<String\> | 是 | 员工编码列表，最多 200 条，不允许空值和重复 |
| operatorId | String | 否 | 操作人ID，用于历史记录 |
| operatorName | String | 否 | 操作人姓名，用于历史记录 |

### 请求参数示例

```
Content-Type: application/x-www-form-urlencoded

talentCodes=30028&talentCodes=60071&operatorId=10001&operatorName=管理员
```

> 列表类型参数通过同名参数多次传递，如 `talentCodes=30028&talentCodes=60071`。

### 响应

```json
{
  "success": true,
  "data": {
    "operationType": "batch_create_by_default",
    "totalCount": 2,
    "successCount": 2,
    "success": true,
    "message": "未建档员工批量建档成功"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 校验与权限

- talentCodes 必填，最多 200 条，不允许空值和重复
- 系统管理员可给全部员工建档
- 有部门范围时，只能给 deptScopes 内员工建档
- 普通员工/无部门范围时禁止操作
- 员工必须存在于 IPS（ip_db.talent_person），不存在则整体失败
- 员工必须在 attendance_archive 中无未删除档案（is_deleted=0），已建档则整体失败
- 员工所属组织必须有默认配置（attendance_org_default_config），且 attendancePolicyCode、leavePolicyCode、defaultShiftCode 均不能为空，否则整体失败

### 默认值

| 字段 | 值 |
|------|------|
| attendanceNo | = talentCode |
| attendancePolicyCode | 组织默认配置 |
| leavePolicyCode | 组织默认配置 |
| defaultShiftCode | 组织默认配置 |
| isPunchAttendance | 1 |
| isAutoSchedule | 1 |
| scheduleMode | fixed |
| status | 1 |
| isDeleted | 0 |

### 历史记录

- 每创建一条档案，写一条 attendance_archive_history
- change_type = batch_create_by_default，change_mode = batch
- before_snapshot = null，after_snapshot = 创建后的档案 JSON
