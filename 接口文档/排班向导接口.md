# 排班向导接口

基础路径：`/api/attendance/schedule/wizard`

统一返回结构：`ReturnInfo<T>`

公共规则：
- Content-Type：`application/x-www-form-urlencoded`，参数通过表单提交
- tokenID 通过 query 参数传递，如 `?tokenID=xxx`
- 列表类型参数通过同名参数多次传递，如 `memberTalentCodes=30028&memberTalentCodes=60071`

---

## 1. G1 排班向导参数查询

`POST /api/attendance/schedule/wizard/params`

> 只读接口，不写入数据库。返回当前用户进入排班向导时需要的基础参数。

### 请求参数

无请求参数。

### 响应

系统管理员（全量数据，只读）：

```json
{

  "data": {
    "maxScheduleEndDate": "2026-12-31",
    "orgScopes": [
      { "deptCode": "100", "deptName": "研发部" },
      { "deptCode": "200", "deptName": "财务部" }
    ],
    "attendanceGroups": [
      {
        "groupId": 1001,
        "groupName": "研发排班组",
        "attendanceOrgCode": "100",
        "attendanceOrgName": "研发部"
      },
      {
        "groupId": 1002,
        "groupName": "财务排班组",
        "attendanceOrgCode": "200",
        "attendanceOrgName": "财务部"
      }
    ],
    "rotationRules": [
      { "rotationRuleCode": "R001", "rotationRuleName": "三班倒" },
      { "rotationRuleCode": "R002", "rotationRuleName": "全局规则" }
    ],
    "canSubmit": false,
    "readonlyReason": "系统管理员仅允许查看排班向导参数"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

有部门范围的考勤员（范围内数据，可提交）：

```json
{
  "success": true,
  "data": {
    "maxScheduleEndDate": "2026-12-31",

      { "deptCode": "100", "deptName": "研发部" },
      { "deptCode": "200", "deptName": "财务部" }
    ],
    "attendanceGroups": [
      {
        "groupId": 1001,
        "groupName": "研发排班组",
        "attendanceOrgCode": "100",
        "attendanceOrgName": "研发部"
      }
    ],
    "rotationRules": [
      { "rotationRuleCode": "R001", "rotationRuleName": "三班倒" }
    ],
    "canSubmit": true,
    "readonlyReason": null
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

普通员工（空数据，只读）：

```json
{
  "success": true,
  "data": {
    "maxScheduleEndDate": "2026-12-31",
    "orgScopes": [],
    "attendanceGroups": [],
    "rotationRules": [],

  "messageType": 0

```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| maxScheduleEndDate | String | 最大可排班结束日期，格式 yyyy-MM-dd，来源于 yml 配置 |
| orgScopes | List | 当前用户可操作组织范围 |
| orgScopes[].deptCode | String | 组织编码 |
| orgScopes[].deptName | String | 组织名称 |
| attendanceGroups | List | 当前用户可选考勤组 |
| attendanceGroups[].groupId | Long | 考勤组 ID |
| attendanceGroups[].groupName | String | 考勤组名称 |
| attendanceGroups[].attendanceOrgCode | String | 考勤组所属组织编码 |
| attendanceGroups[].attendanceOrgName | String | 考勤组所属组织名称，来源于 IPS talent_organization |
| rotationRules | List | 可用轮班规则 |
| rotationRules[].rotationRuleCode | String | 轮班规则编码 |
| rotationRules[].rotationRuleName | String | 轮班规则名称 |
| canSubmit | Boolean | 是否允许提交排班 |
| readonlyReason | String | 不允许提交原因，可提交时为 null |

### 权限与数据范围规则

**角色与 canSubmit：**

| 角色 | canSubmit | readonlyReason |
|------|-----------|----------------|
| 系统管理员 | false | 系统管理员仅允许查看排班向导参数 |
| 有部门范围的考勤员 | true | null |
| 普通员工 | false | 当前用户无排班向导操作权限 |

**组织范围（orgScopes）：**

- 系统管理员：返回全部有效组织（从考勤组 + 轮班规则中收集组织编码，通过 IPS 补充名称）
- 有部门范围的用户：返回 `UserAuthContext.deptScopeItems` 中的组织
- 普通员工：返回空数组

**考勤组（attendanceGroups）：**

- 只返回 `is_deleted=0` 且 `status=1` 的考勤组
- 系统管理员返回全部有效考勤组
- 非系统管理员只返回 `owner_dept_code` 在当前用户 deptScopes 内的考勤组
- `attendanceOrgName` 通过 `ipdb.talent_organization` 按组织编码实时补充

**轮班规则（rotationRules）：**

- 只返回 `is_deleted=0` 且 `status=1` 的规则
- 只返回在 `attendance_rotation_rule_detail` 中存在未删除明细的规则
- 系统管理员返回全部有效轮班规则
- 非系统管理员只返回当前部门范围内的轮班规则
- `organization_code` 为空视为全局规则，返回给有操作权限的用户
- `organization_code` 不为空时必须落在当前用户 deptScopes 内

**最大排班结束日期（maxScheduleEndDate）：**

- 从 yml 配置 `attendance.schedule.wizard.max-schedule-end-date` 读取
- 格式固定为 `yyyy-MM-dd`
- 未配置时抛出 BusinessException
- 格式错误时抛出 BusinessException

## 2. G2 排班向导成员分页查询

`POST /api/attendance/schedule/wizard/member/page`

> 只读接口，查询当前用户权限范围内可被排班向导选择的已建档员工。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deptCode | String | 否 | 组织编码 |
| groupId | Long | 否 | 考勤组 ID，按考勤组成员关系过滤 |
| talentCode | String | 否 | 员工编码模糊查询 |
| talentName | String | 否 | 员工姓名模糊查询 |
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 20，最大 100 |

### 请求示例

```
Content-Type: application/x-www-form-urlencoded

deptCode=100&groupId=1001&talentCode=300&talentName=张&pageNo=1&pageSize=20
```

### 响应

```json
{
  "success": true,
  "data": [
    {
      "talentCode": "30028",
      "talentName": "张三",
      "deptCode": "100",
      "deptName": "研发部",
      "attendanceGroupId": 1001,
      "attendanceGroupName": "研发排班组",
      "archiveId": 123456789,
      "canSchedule": true,
      "cannotScheduleReason": ""
    }
  ],
  "total": 1,
  "currPage": 1,
  "message": "ok",
  "messageType": 0
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| data | List | 成员列表 |
| data[].talentCode | String | 员工编码 |
| data[].talentName | String | 员工姓名，来源于 IPS |
| data[].deptCode | String | 组织编码 |
| data[].deptName | String | 组织名称，来源于 IPS talent_organization |
| data[].attendanceGroupId | Long | 考勤组 ID，未关联考勤组时为 null |
| data[].attendanceGroupName | String | 考勤组名称，未关联考勤组时为 null |
| data[].archiveId | Long | 考勤档案 ID |
| data[].canSchedule | Boolean | 是否可排班，第一版默认 true |
| data[].cannotScheduleReason | String | 不可排班原因，第一版返回空字符串 |
| total | Long | 总记录数（顶层字段） |
| currPage | Integer | 当前页码（顶层字段） |

### 权限与数据范围规则

**角色数据范围：**

| 角色 | 数据范围 |
|------|----------|
| 系统管理员 | 全部已建档员工 |
| 有部门范围的考勤员 | 权限范围内员工 |
| 普通员工 | 空分页 |

**筛选条件：**

- `deptCode`：按员工组织过滤，必须落在当前用户 deptScopes 内，越权返回空分页
- `groupId`：按考勤组成员关系过滤；考勤组必须存在且启用。返回结果仍按当前用户 deptScopes 过滤成员，不按考勤组 ownerDeptCode 拦截整个组
- `talentCode`：按员工编码模糊查询
- `talentName`：按员工姓名模糊查询（通过 IPS 预匹配编码后再过滤档案）

**成员查询规则：**

- 只返回 `attendance_archive.is_deleted=0` 且 `status=1` 的有效档案员工
- 只返回 IPS 中存在的员工
- 未建档、已删除档案、IPS 不存在的员工不返回
- 同一员工只返回一条记录
- 未关联考勤组的员工仍返回，`attendanceGroupId` 为 null
- 结果按员工编码稳定排序

**分页规则：**

- `pageNo` 默认 1，小于 1 按 1 处理
- `pageSize` 默认 20，小于 1 按 20 处理，最大 100

## 3. G3 排班向导草案生成

`POST /api/attendance/schedule/wizard/generate`

> 只读接口，生成排班草案并检测冲突，不写库。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| startDate | String | 是 | 排班开始日期，格式 yyyy-MM-dd |
| endDate | String | 是 | 排班结束日期，格式 yyyy-MM-dd |
| rotationRuleCode | String | 是 | 轮班规则编码 |
| rotationAnchorDate | String | 否 | 轮班规则开始于，格式 yyyy-MM-dd，不传默认 startDate |
| rotationStartSeq | Integer | 否 | 锚点日期对应的轮班序号，不传默认轮班规则明细中最小 seqNo |
| holidayHandleMode | String | 是 | 节假日处理，第一版只支持 DELAY |
| memberTalentCodes | List\<String\> | 是 | 员工编码列表，不能为空，最大 200 人 |

### 请求示例

```
Content-Type: application/x-www-form-urlencoded

startDate=2026-06-01&endDate=2026-06-30&rotationRuleCode=R001&rotationAnchorDate=2026-06-01&rotationStartSeq=1&holidayHandleMode=DELAY&memberTalentCodes=30028&memberTalentCodes=60071
```

### 响应

```json
{
  "success": true,
  "data": {
    "draftItems": [
      {
        "talentCode": "30028",
        "talentName": "张三",
        "scheduleDate": "2026-06-01",
        "rotationSeq": 1,
        "shiftCode": "S01",
        "shiftName": "早班",
        "isRestDay": false,
        "conflictFlag": false,
        "conflictReason": null
      }
    ],
    "conflicts": [],
    "invalidMembers": [],
    "summary": {
      "memberCount": 2,
      "dateCount": 30,
      "draftCount": 60,
      "conflictCount": 0,
      "invalidMemberCount": 0
    },
    "canSubmit": true
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 参数校验

- startDate、endDate、rotationRuleCode、holidayHandleMode、memberTalentCodes 必填
- rotationAnchorDate 不传时默认 startDate
- rotationStartSeq 不传时默认轮班规则明细中最小 seqNo
- `endDate` 不能小于 `startDate`
- 日期范围最大 366 天
- 员工数量最大 200 人
- `holidayHandleMode` 第一版只允许 `DELAY`
- `endDate` 不能超过 G1 配置的最大可排班结束日期

### 轮班规则校验

- 规则必须存在、启用（status=1）、未删除（is_deleted=0）
- 规则必须有未删除的明细
- `rotationStartSeq` 必须存在于明细中
- 非系统管理员使用组织级规则时，规则组织必须在权限范围内

### 成员校验

- 员工编码自动去重
- 员工必须存在于 IPS
- 员工必须有有效考勤档案（is_deleted=0, status=1）
- 员工档案考勤组织必须在权限范围内
- 未通过校验的员工进入 `invalidMembers`，接口不失败

### 生成规则

- 按 startDate 到 endDate 逐天生成
- 轮班明细按 seqNo 升序形成循环周期
- rotationAnchorDate 命中 rotationStartSeq
- 每个日期根据锚点和周期计算命中的 seqNo
- 超过最后一个 seqNo 回到第一个（循环）
- 明细 dateType 为休息日或 shiftCode 为空时 isRestDay=true

### 冲突检测

- 查询 attendance_schedule_day 中同员工、同日期的未删除记录
- 已有记录存在时标记冲突：conflictFlag=true，conflictReason="该日期已存在排班"
- 只检测冲突，不覆盖不删除已有排班

### canSubmit 判断

| 条件 | canSubmit |
|------|-----------|
| 系统管理员 | false |
| 普通员工 | false |
| 有冲突 | false |
| 有无效成员 | false |
| 无冲突、无无效成员、有部门范围 | true |

## 4. G4 排班向导提交

`POST /api/attendance/schedule/wizard/submit`

> 写库接口，后端重新生成排班并检测冲突后写入 attendance_schedule_day。事务操作。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| startDate | String | 是 | 排班开始日期，格式 yyyy-MM-dd |
| endDate | String | 是 | 排班结束日期，格式 yyyy-MM-dd |
| rotationRuleCode | String | 是 | 轮班规则编码 |
| rotationAnchorDate | String | 否 | 轮班规则开始于，格式 yyyy-MM-dd，不传默认 startDate |
| rotationStartSeq | Integer | 否 | 锚点日期对应的轮班序号，不传默认轮班规则明细中最小 seqNo |
| holidayHandleMode | String | 是 | 节假日处理，第一版只支持 DELAY |
| memberTalentCodes | List\<String\> | 是 | 员工编码列表，不能为空，最大 200 人 |
| operatorId | String | 否 | 操作人 ID |
| operatorName | String | 否 | 操作人姓名 |

### 请求示例

```
Content-Type: application/x-www-form-urlencoded

startDate=2026-06-01&endDate=2026-06-30&rotationRuleCode=R001&rotationAnchorDate=2026-06-01&rotationStartSeq=1&holidayHandleMode=DELAY&memberTalentCodes=30028&memberTalentCodes=60071&operatorId=90001&operatorName=考勤员
```

### 响应

```json
{
  "success": true,
  "data": {
    "success": true,
    "insertCount": 60,
    "memberCount": 2,
    "dateCount": 30,
    "conflictCount": 0,
    "invalidMemberCount": 0,
    "message": "排班提交成功，共写入 60 条记录"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 权限规则

| 角色 | 是否允许提交 |
|------|-------------|
| 系统管理员 | 禁止 |
| HR | 禁止 |
| 部门负责人 | 禁止 |
| 普通员工 | 禁止 |
| 有部门范围的考勤员 | 允许 |

### 提交规则

- 后端使用请求参数重新生成排班结果，不信任前端草案
- 生成逻辑与 G3 一致（轮班周期循环）
- 写库前重新查询 attendance_schedule_day 检测冲突
- 任一冲突 → 整体失败（第一版不覆盖、不跳过）
- 任一员工无效（IPS 不存在/未建档/越权）→ 整体失败
- 整个提交过程在事务内完成，任一写入失败整体回滚

### 写入字段

| 字段 | 写入规则 |
|------|----------|
| schedule_day_id | IdWorker 生成唯一 ID |
| talent_code | 员工编码 |
| schedule_date | 排班日期 |
| shift_code | 轮班明细班次编码，休息日为空字符串 |
| date_type | 轮班明细日期类型 |
| source_type | 固定写 `排班向导` |
| source_biz_type | 固定写 `轮班规则` |
| attendance_policy_code | 来自员工考勤档案 |
| status | 固定写 1 |
| is_deleted | 固定写 0 |
| remark | 固定写 `排班向导按轮班规则生成` |
