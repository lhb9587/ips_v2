# 考勤计算接口

基础路径：`/api/attendance/calc`

统一返回结构：`ReturnInfo<T>`

公共规则：
- Content-Type：`application/x-www-form-urlencoded`
- tokenID 通过 query 参数或请求头传入
- 涉及数据权限的接口必须标注 `@ScopeAuthRequired`
- 部门筛选传入父部门时，必须按 `UserAuthContext.deptScopeTree` 展开子部门，再与 `deptScopes` 取交集
- 分页接口返回时，`data` 直接放列表，`total` 放总数，`currPage` 放当前页

## 状态口径

| 状态 | 说明 |
|------|------|
| `not_calculated` | 未计算，周期状态已初始化但未生成有效结果 |
| `pending` | 待计算，打卡、排班、补签、请假、出差、加班变化后需要重算 |
| `calculated` | 已计算，当前周期已有有效计算结果 |

### 处理规则

1. 接口标注 `@ScopeAuthRequired`，读取 `UserAuthContextHolder.getRequired()`。

5. 周期选项后端生成最近 12 个自然月，按当前月倒序。
6. 默认周期取服务器当前日期所在月份。
7. 该接口只读，不写库，不触发计算。

## 2. 考勤周期状态初始化

`POST /api/attendance/calc/cycle-state/init`

按有效考勤档案和指定周期生成员工周期状态，默认 `not_calculated`。用于三个页签（未计算、待计算、已计算）的数据基础。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| periodCode | String | 是 | 周期编码，格式 `yyyyMM` |
| attendancePolicyCode | String | 否 | 考勤制度编码 |
| deptCode | String | 否 | 部门编码 |
| talentCode | String | 否 | 员工编码 |
| talentName | String | 否 | 员工姓名 |

### 返回字段

| 字段 | 类型 | 说明 |
|------|------|------|
| periodCode | String | 周期编码 |
| periodStartDate | String | 周期开始日期 |
| periodEndDate | String | 周期结束日期 |
| matchedArchiveCount | int | 匹配到的有效档案数 |
| existingStateCount | int | 已存在的周期状态数 |
| createdStateCount | int | 本次新建的周期状态数 |
| success | boolean | 是否成功 |
| message | String | 消息 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "periodCode": "202605",
    "periodStartDate": "2026-05-01",
    "periodEndDate": "2026-05-31",
    "matchedArchiveCount": 50,
    "existingStateCount": 30,
    "createdStateCount": 20,
    "success": true,
    "message": "初始化完成"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 参数校验

1. `periodCode` 必填，格式 `yyyyMM`。
2. `periodCode` 格式非法时返回 `INVALID_PARAM`。

### 权限规则

1. 接口标注 `@ScopeAuthRequired`。
2. 系统管理员可初始化全部员工。
3. 考勤员只能初始化自己权限范围内员工（`ctx.getDeptScopes()`）。
4. 考勤员 `deptScopes` 为空时返回 `AUTH_FORBIDDEN`。
5. HR、部门负责人、普通员工第一版禁止，返回 `AUTH_FORBIDDEN`。

### 部门范围规则

1. 系统管理员传了 `deptCode` 按该部门过滤，不传则查全量。
2. 考勤员不传 `deptCode` 时，只能查 `deptScopes` 内员工。
3. 考勤员传了 `deptCode` 时，按 `ctx.getDeptScopeTree()` 展开为父部门和全部子部门，再与 `deptScopes` 取交集。

### 员工范围规则

1. 来源表：`attendance_archive`，条件 `is_deleted=0 AND status=1`。
2. 按 `attendance_org_code` 做部门过滤。
3. 按 `attendance_policy_code` 做考勤制度过滤。
4. 按 `talent_code` 做员工编码精确过滤。
5. `talentName` 通过 IPS `findTalentCodesByName` 模糊匹配员工编码后再过滤档案。

### 初始化规则

1. 查询符合条件的有效档案。
2. 批量查询这些员工在该 `periodCode` 下已存在的 `attendance_calc_cycle_state`。
3. 已存在的不处理（不改变 `calculated`、`pending` 状态）。
4. 不存在的插入新状态，默认值：
   - `status=not_calculated`
   - `period_code=periodCode`
   - `period_start_date=周期第一天`
   - `period_end_date=周期最后一天`
   - `talent_code=档案员工编码`
   - `user_id=IPS 查询得到，取不到允许空`
   - `dirty_from_date=null`
   - `dirty_to_date=null`
   - `trigger_reason=周期初始化`
   - `calc_version=0`
   - `is_deleted=0`

### 幂等规则

1. 同一 `talent_code + period_code` 已存在有效记录时，不重复插入。
2. 已存在 `calculated` 不改回 `not_calculated`。
3. 已存在 `pending` 不改回 `not_calculated`。
4. 重复调用只补缺失员工。

### 事务规则

1. 整体 `@Transactional`。
2. 批量插入按 200 条一批。
3. 插入后回写 `state_id=id`。
4. 任一批次失败整体回滚。

### 服务清单

| 序号 | 服务名 | 类型 | 作用 | 是否完成 |
|------|--------|------|------|----------|
| 1 | AttendanceCalcCycleStateInitService | 初始化服务 | 校验参数和权限，查档案、去重、批量插入周期状态 | 已完成 |
| 2 | AttendanceArchiveMapper.listCalcInitArchives | SQL | 查有效档案，按部门/制度/员工编码/姓名过滤 | 已完成 |
| 3 | AttendanceCalcCycleStateMapper.findExistingByPeriodAndTalentCodes | SQL | 批量查询已存在的周期状态 | 已完成 |
| 4 | AttendanceCalcCycleStateMapper.batchInsertStates | SQL | 批量插入周期状态 | 已完成 |
| 5 | AttendanceCalcCycleStateMapper.batchUpdateStateIds | SQL | 批量回写 state_id | 已完成 |
| 6 | IpsPersonMapper.findTalentCodesByName | SQL | 按姓名模糊查询员工编码 | 已复用 |
| 7 | IpsPersonMapper.findByTalentCodes | SQL | 批量查询员工 userId | 已复用 |

### 参数校验

1. `periodCode` 必填，格式 `yyyyMM`。
2. `periodCode` 格式非法时返回 `INVALID_PARAM`。
3. `pageNo` 默认 1，`pageSize` 默认 20，最大 200。

### 权限规则

1. 接口标注 `@ScopeAuthRequired`。
2. 只允许系统管理员和考勤员访问，其他角色返回 `AUTH_FORBIDDEN`。
3. 系统管理员可查询全部，传 `deptCode` 时按该部门过滤。
4. 考勤员只能查 `deptScopes` 范围内员工。
5. 考勤员传 `deptCode` 时，展开父部门及子部门后与 `deptScopes` 取交集。
6. 交集为空直接返回空分页，不进 SQL 查全量。

### 查询规则

1. 主表 `attendance_calc_cycle_state s`。
2. JOIN `attendance_archive a` 取考勤组织和制度。
3. JOIN `ip_db.talent_person tp` 取员工姓名。
4. LEFT JOIN `ip_db.talent_organization org` 取组织名称。
5. LEFT JOIN `attendance_policy p` 取制度名称。
6. 核心条件：`s.status = 'not_calculated' AND s.is_deleted = 0`。
7. `talentName` 直接 JOIN `ip_db.talent_person` 后 LIKE 查询。
8. 排序：`attendance_org_code ASC, talent_code ASC`。

### 处理规则

1. 该接口只读，不写库。
2. 不初始化周期状态，不触发计算。
3. 不查询结果表。
4. `queryDeptCodes` 为空集合时，Service 直接返回空分页。

### 与 S7-06-03 的区别

| 对比项 | S7-06-03 未计算 | S7-06-04 待计算 |
|--------|----------------|----------------|
| 状态 | `not_calculated` | `pending` |

| 排序 | `org_code ASC, talent_code ASC` | `update_time DESC` 优先 |

1. 复用通用 mapper `countCycleStatePage` / `listCycleStatePage`，`status='pending'`。
2. 排序：`s.update_time DESC, a.attendance_org_code ASC, s.talent_code ASC`，最新变更排在前面。
3. 其他 JOIN 和筛选逻辑同 S7-06-03。

### 处理规则

1. 该接口只读，不写库。
2. 不触发计算，不重新判断脏数据。
3. 不扫描打卡、排班、单据原始表。

## 5. 已计算列表分页查询

`POST /api/attendance/calc/calculated/page`

查询指定周期内状态为 `calculated` 的员工列表，作为"已计算汇总模式"和"已计算明细模式"的入口。只读，不写库。

### 请求参数

复用 `AttendanceCalcCycleStatePageRequest`，字段同 S7-06-03。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| periodCode | String | 是 | 周期编码，格式 `yyyyMM` |
| attendancePolicyCode | String | 否 | 考勤制度编码 |
| deptCode | String | 否 | 部门编码 |
| talentCode | String | 否 | 员工编码 |
| talentName | String | 否 | 员工姓名 |
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 20，最大 200 |

### 返回字段

复用 `AttendanceCalcCycleStatePageItemVO`，已计算状态额外返回查看标识。

| 字段 | 类型 | 说明 |
|------|------|------|
| stateId | Long | 周期状态 ID |
| talentCode | String | 员工编码 |
| talentName | String | 员工姓名 |
| attendanceOrgCode | String | 考勤组织编码 |
| attendanceOrgName | String | 考勤组织名称 |
| attendancePolicyCode | String | 考勤制度编码 |
| attendancePolicyName | String | 考勤制度名称 |
| periodCode | String | 周期编码 |
| periodStartDate | String | 周期开始日期 |
| periodEndDate | String | 周期结束日期 |
| calcStatus | String | 固定 `calculated` |
| calcStatusName | String | 固定 `已计算` |
| dirtyFromDate | String | 需要重算开始日期 |
| dirtyToDate | String | 需要重算结束日期 |
| lastCalcTime | String | 最后计算时间 |
| triggerReason | String | 触发原因 |

| resultSummaryStatus | String | 结果汇总状态，固定 `ready` |
| canViewSummary | Boolean | 是否可查看汇总，固定 `true` |

### 三个页签对比

| 对比项 | S7-06-03 未计算 | S7-06-04 待计算 | S7-06-05 已计算 |
|--------|----------------|----------------|----------------|
| 状态 | `not_calculated` | `pending` | `calculated` |
| 额外字段 | 无 | `dirtyFromDate`、`dirtyToDate`、`calcVersion` | `calcVersion`、`resultSummaryStatus`、`canViewSummary`、`canViewDetail` |
| 进入条件 | 周期初始化时写入 | 打卡/排班/单据变更后标记 | 计算完成后更新 |
| 下级入口 | 无 | 无 | 汇总查询、明细查询 |

### 权限规则

同 S7-06-03：只允许系统管理员和考勤员，HR/部门负责人/普通员工禁止。

### 查询规则

1. 复用通用 mapper `countCycleStatePage` / `listCycleStatePage`，`status='calculated'`。
2. Service 层补 `calcStatusName=已计算`、`resultSummaryStatus=ready`、`canViewSummary=true`、`canViewDetail=true`。
3. 其他 JOIN 和筛选逻辑同 S7-06-03。

### 处理规则

1. 该接口只读，不写库。
2. 不现场重新计算。
3. 不返回汇总矩阵或明细表，点击员工后走独立接口。

### 下级接口

点击某个已计算员工后进入：
- 已计算汇总查询：`POST /api/attendance/calc/result/summary/page`
- 已计算明细查询：`POST /api/attendance/calc/result/detail/page`
