# 考勤计算接口

基础路径：`/api/attendance/calc`

统一返回结构：`ReturnInfo<T>`

公共规则：

| 规则 | 说明 |
|------|------|
| 请求方式 | 全部使用 `POST` |
| 参数方式 | 默认表单传参，不使用 `@RequestBody` |
| token | `tokenID` 通过 query 参数或请求头传入 |
| 响应结构 | 分页接口 `data` 直接返回列表，`total` 放总数，`currPage` 放当前页 |
| 权限范围 | 涉及员工范围的接口必须标注 `@ScopeAuthRequired` |
| 部门筛选 | 传入父部门时，必须按 `UserAuthContext.deptScopeTree` 展开子部门，再与 `deptScopes` 取交集 |
| 查询原则 | 查询接口只读结果表，不现场重新计算 |

## 状态口径

| 状态 | 说明 |
|------|------|
| `not_calculated` | 未计算，周期状态已初始化但没有有效计算结果 |
| `pending` | 待计算，打卡、排班、补签、请假、出差、加班变化后需要重算 |
| `processing` | 计算中，任务已抢占该员工周期，其他任务不能重复处理 |
| `calculated` | 已计算，当前周期已有有效计算结果 |

## 1. 考勤计算参数查询

`POST /api/attendance/calc/params`

### 作用

返回考勤计算页面初始化参数。只读，不写库。

### 请求参数

无业务参数。

### 返回字段

| 字段 | 说明 |
|------|------|

## 2. 考勤周期状态初始化

`POST /api/attendance/calc/cycle-state/init`

### 作用

按有效考勤档案和指定周期生成员工周期状态，默认状态为 `not_calculated`。

### 请求参数

| 字段 | 必填 | 说明 |
|------|------|------|
| periodCode | 是 | 周期编码，格式 `yyyyMM` |
| attendancePolicyCode | 否 | 考勤制度编码 |
| deptCode | 否 | 部门编码，支持父部门展开 |
| talentCode | 否 | 员工编码 |
| talentName | 否 | 员工姓名 |

### 返回字段

| 字段 | 说明 |
|------|------|
| periodCode | 周期编码 |
| periodStartDate | 周期开始日期 |
| periodEndDate | 周期结束日期 |
| matchedArchiveCount | 匹配到的有效档案数 |
| existingStateCount | 已有周期状态数 |
| createdStateCount | 本次新建状态数 |
| success | 是否成功 |
| message | 结果说明 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "periodCode": "202605",
    "periodStartDate": "2026-05-01",
    "periodEndDate": "2026-05-31",
    "matchedArchiveCount": 50,
    "existingStateCount": 30,
    "createdStateCount": 20,
    "success": true,
    "message": "初始化完成"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 处理规则

1. 只初始化有效考勤档案员工。
2. 已存在同员工同周期状态时不重复插入。
3. 已计算、待计算状态不能被初始化覆盖成未计算。
4. 考勤员只能初始化自己权限范围内员工。

## 6. 开始计算

`POST /api/attendance/calc/start`

### 作用

对当前筛选范围内 `not_calculated` 和 `pending` 员工发起计算。

### 请求参数

| 字段 | 必填 | 说明 |
|------|------|------|
| periodCode | 是 | 周期编码，格式 `yyyyMM` |
| attendancePolicyCode | 否 | 考勤制度编码 |
| deptCode | 否 | 部门编码，支持父部门展开 |
| talentCode | 否 | 员工编码 |
| talentName | 否 | 员工姓名 |

### 返回字段

| 字段 | 说明 |
|------|------|
| taskId | 计算任务 ID |
| taskStatus | 任务状态 |
| periodCode | 周期编码 |
| totalCount | 总人数 |
| successCount | 成功人数 |
| failCount | 失败人数 |
| successTalentCodes | 成功员工编码 |
| failItems | 失败明细 |
| message | 结果说明 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "taskId": 100,
    "taskStatus": "success",
    "periodCode": "202605",
    "totalCount": 10,
    "successCount": 8,
    "failCount": 2,
    "successTalentCodes": ["10053", "10465", "11318"],
    "failItems": [
      {
        "talentCode": "30028",
        "talentName": "赵六",
        "reason": "未找到排班记录"
      },
      {
        "talentCode": "30029",
        "talentName": "钱七",
        "reason": "考勤制度配置缺失"
      }
    ],
    "message": "计算完成，成功 8 人，失败 2 人"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 处理规则

1. 创建计算任务。
2. 按员工分片执行。
3. 同员工同周期通过并发抢占控制，不能被多个任务同时计算。
4. 成功员工状态更新为 `calculated`。
5. 失败员工写入任务明细，不影响成功员工结果。

## 15. 考勤计算结果导出

### 作用

### 请求参数

| attendancePolicyCode | 否 | 考勤制度编码 |
| talentCode | 否 | 员工编码模糊匹配 |

### 响应

返回 `ReturnInfo<ExportFileVO>`，后端生成 Excel 文件到磁盘，前端通过 `filePath` 下载。

| 字段 | 说明 |
|------|------|
| filePath | 前端下载路径，如 `/template/ip_attendance/attendance_calc_result/2026-05-20/1779000000000/考勤计算结果_202712.xlsx` |
| fileName | 文件名，如 `考勤计算结果_202712.xlsx` |

### Excel 列

| 列名 | 对应字段 |
|------|----------|
| 周期编码 | periodCode |

| 考勤组织名称 | attendanceOrgName |
| 考勤制度编码 | attendancePolicyCode |
| 考勤制度名称 | attendancePolicyName |

| 最后计算时间 | lastCalcTime |
| 计算版本 | calcVersion |
| 触发原因 | triggerReason |

### 处理规则

1. **exportMode**：必填，只允许 `selected` 或 `all`。
2. **periodCode**：必填，指定导出的考勤周期。
3. **selected 模式**：`selectedTalentCodes` 必填，逗号分隔解析后去重，按指定员工编码 IN 查询。
4. **all 模式**：按 `periodCode`/`deptCode`/`attendancePolicyCode`/`talentCode`/`talentName` 筛选条件导出全部，不分页。
5. **权限校验**：只允许系统管理员和考勤员访问。部门范围通过 `resolveDeptCodes` 解析，导出全部只导出当前用户权限范围内的数据。
6. **数据来源**：`attendance_calc_cycle_state` 关联 `attendance_archive`，只导出 `status IN ('已计算', 'calculated')` 的员工。
7. **导出上限**：最大 10000 条，超出提示缩小筛选范围。
8. **导出文件**：后端生成 Excel 写入磁盘，返回 `ExportFileVO`（含 `filePath` 和 `fileName`），前端通过路径下载。
