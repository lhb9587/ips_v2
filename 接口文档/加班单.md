## 说明

后台管理端加班单用于在当前用户权限范围内查看加班单，并执行提交生效、反审批、废弃、导出等公共动作。

加班单创建、编辑、保存草稿、提交审批等员工自助端能力，统一沿用”我要加班”，后台管理端不重复建设。加班单详情与请假单保持一致，使用 `POST /api/overtime/request/admin/detail` 作为后台和员工自助共用的统一详情入口，不单独新增 `self/detail`。

员工端加班提交不单独提供 `/self/submit` 接口。提交按钮统一调用 `/api/overtime/request/self/save`，通过 `submitFlag=1` 表示保存后立即提交审批；`submitFlag=0` 或空表示仅保存草稿。

提交生效需要写入审批中心并直接置为已通过，不进入待办流转。已通过加班单后续用于考勤计算和调休生成，调休按加班时长 1:1 生成，未使用时按规则 3 个月失效。

## 1. 加班单列表分页查询

`POST /api/overtime/request/admin/page`

后台管理端按当前用户权限范围分页查询加班单列表。

| talentCode | String | 否 | 员工编码，模糊查询 |
| talentName | String | 否 | 员工姓名，模糊查询 |
| deptCode | String | 否 | 部门编码；传父部门时后端按权限树展开子部门 |

## 3. 加班单提交生效

`POST /api/overtime/request/admin/direct-pass`

将加班单直接置为已通过，跳过审批流程。仅系统管理员和考勤员可操作。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| tokenID | String | 是 | 登录令牌，可放请求头或请求参数 |
| overtimeRequestId | Long | 是 | 加班单主键业务 ID |
| overtimeRequestIds | String | 否 | 批量加班单ID，逗号分隔，优先使用；不传则使用 overtimeRequestId |

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| overtimeRequestId | Long | 加班单主键业务 ID |
| requestNo | String | 加班单号 |
| instanceId | Long | 审批实例 ID |
| requestStatus | String | 单据状态（已通过） |
| approvalStatus | String | 审批状态（已通过） |
| success | Boolean | 批量操作是否成功 |
| successCount | Integer | 成功操作条数 |
| overtimeRequestIds | List&lt;Long&gt; | 本次操作的加班单ID列表 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "overtimeRequestId": 1001,
    "requestNo": "OT202605270001",
    "instanceId": 90001,
    "requestStatus": "已通过",
    "approvalStatus": "已通过"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 业务规则

1. 仅「未提交」「已退回」状态的单据允许提交生效。
2. 已有审批绑定记录的单据不允许重复提交。
3. 操作人信息从登录上下文获取，不依赖前端传参。
4. 内部复用 `ApprovalWorkflowDirectPassService`，自动创建已通过审批实例、绑定业务单据、写提交/同意日志、回写业务状态。

### 权限规则

1. 接口需要 `@ScopeAuthRequired`。
2. 系统管理员可操作全部。
3. 考勤员可操作负责部门范围内数据。
4. HR、部门负责人、组长、普通员工均无权操作。

## 4. 加班单反审批

`POST /api/overtime/request/admin/reverse-approve`

将已通过的加班单撤回为未提交状态，终止审批实例，释放审批绑定。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `overtimeRequestId` | Long | 是 | 加班单主键业务 ID |
| `overtimeRequestIds` | String | 否 | 批量加班单ID，逗号分隔，优先使用；不传则使用 overtimeRequestId |
| `remark` | String | 否 | 备注 |

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `overtimeRequestId` | Long | 加班单主键业务 ID |
| `requestNo` | String | 加班单号 |
| `approvalInstanceId` | Long | 审批实例 ID |
| `beforeStatus` | String | 反审批前状态 |
| `afterStatus` | String | 固定"未提交" |
| `reverseActionId` | Long | 撤回动作日志 ID |
| `success` | Boolean | 批量操作是否成功 |
| `successCount` | Integer | 成功操作条数 |
| `overtimeRequestIds` | List&lt;Long&gt; | 本次操作的加班单ID列表 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "overtimeRequestId": 1001,
    "requestNo": "OT202605270001",
    "approvalInstanceId": 90001,
    "beforeStatus": "已通过",
    "afterStatus": "未提交",
    "reverseActionId": 3002
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 业务规则

1. 仅「已通过」状态的单据允许反审批。
2. 加班单已生成调休台账时不允许反审批。
3. 反审批后写入"撤回"审批动作日志。
4. 审批实例状态置为"已撤回"，单据状态回退为"未提交"，禁用当前审批绑定。
5. 标记相关日期的日历快照为脏数据，触发重算。
6. 操作人信息从登录上下文获取，不依赖前端传参。

### 权限规则

1. 接口需要 `@ScopeAuthRequired`。
2. 系统管理员可操作全部。
3. 考勤员可操作负责部门范围内数据。
4. HR、部门负责人、组长、普通员工均无权操作。

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| overtimeRequestId 为空 | overtimeRequestId 不能为空 |
| 无操作权限 | 无权执行反审批操作 |
| 加班单不存在 | 加班单不存在 |
| 非本人权限范围 | 无权操作该加班单 |
| 状态不允许反审批 | 当前单据状态为「{status}」，不允许反审批 |
| 已生成调休台账 | 该加班单已生成调休台账，无法撤回 |

## 5. 加班单废弃

`POST /api/overtime/request/admin/abandon`

废弃加班单，终止审批实例（如有），将单据状态置为已废弃。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `overtimeRequestId` | Long | 是 | 加班单主键业务 ID |
| `overtimeRequestIds` | String | 否 | 批量加班单ID，逗号分隔，优先使用；不传则使用 overtimeRequestId |
| `remark` | String | 否 | 废弃原因 |

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `overtimeRequestId` | Long | 加班单主键业务 ID |
| `requestNo` | String | 加班单号 |
| `beforeStatus` | String | 废弃前状态 |
| `afterStatus` | String | 固定"已废弃" |
| `approvalInstanceId` | Long | 审批实例 ID（无则为 null） |
| `abandonActionId` | Long | 终止动作日志 ID（无审批实例则为 null） |
| `success` | Boolean | 批量操作是否成功 |
| `successCount` | Integer | 成功操作条数 |
| `overtimeRequestIds` | List&lt;Long&gt; | 本次操作的加班单ID列表 |

### 返回示例

有审批实例的废弃：

```json
{
  "success": true,
  "data": {
    "overtimeRequestId": 1001,
    "requestNo": "OT202605270001",
    "beforeStatus": "审批中",
    "afterStatus": "已废弃",
    "approvalInstanceId": 90001,
    "abandonActionId": 3003
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

无审批实例的废弃（未提交草稿）：

```json
{
  "success": true,
  "data": {
    "overtimeRequestId": 1002,
    "requestNo": "OT202605280001",
    "beforeStatus": "未提交",
    "afterStatus": "已废弃",
    "approvalInstanceId": null,
    "abandonActionId": null
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

### 业务规则

1. 允许废弃：未提交、已退回、审批中、已通过。
2. 禁止废弃：已废弃（不可重复操作）。
3. 已通过状态且已生成调休台账时不允许废弃。
4. 有审批实例时：关闭待处理审批任务、关闭待审批人、写"终止"审批动作日志、审批实例状态置为"已废弃"、禁用当前审批绑定。
5. 无审批实例时：直接更新单据状态为"已废弃"。
6. 标记相关日期的日历快照为脏数据，触发重算。
7. 操作人信息从登录上下文获取，不依赖前端传参。

2. 系统管理员可操作全部。

| 加班单不存在 | 加班单不存在 |

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `overtimeRequestId` | Long | 加班单ID |
| `requestNo` | String | 加班单号 |
| `status` | String | 当前状态：`未提交` 或 `审批中` |
| `submitted` | Boolean | 是否已提交审批 |

| `applyOvertimeHours` | BigDecimal | 申请加班小时数 |
| `applyOvertimeMinutes` | Integer | 申请加班分钟数 |

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| 加班日期为空 | 加班日期不能为空 |
| 开始时间为空 | 加班开始时间不能为空 |
| 结束时间为空 | 加班结束时间不能为空 |
| 结束时间不大于开始时间 | 加班结束时间必须大于开始时间 |
| 休息时长小于0 | 休息时长不能小于0 |
| 休息时长大于等于总时长 | 休息时长不能大于等于加班总时长 |
| 加班类型非法（非空时校验） | 加班类型编码非法，仅允许 OT1/OT2/OT3 |

## 11. 【我要加班】删除加班草稿

`POST /api/overtime/request/self/delete`

### 作用

当前员工删除自己的未提交或已退回加班单。支持批量删除，逻辑删除主表、明细表和附件关联表。删除已退回单据时自动禁用旧审批绑定。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。
- 只能删除当前登录员工自己的未提交或已退回的单据。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `overtimeRequestId` | Long | 否 | 加班单业务 ID，兼容单条 |
| `overtimeRequestIds` | String | 否 | 加班单业务 ID，批量，逗号分隔，优先使用 |

两个参数至少传一个。`overtimeRequestIds` 优先级高于 `overtimeRequestId`。

### 返回字段

`ReturnInfo<OvertimeRequestSelfDeleteResultVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `successCount` | Integer | 成功删除数量 |
| `overtimeRequestIds` | List\<Long\> | 成功删除的加班单 ID 列表 |
| `deleted` | Boolean | 是否删除成功 |
| `overtimeRequestId` | Long | 兼容：第一条加班单 ID |
| `requestNo` | String | 兼容：第一条加班单号 |

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| overtimeRequestId 和 overtimeRequestIds 都为空 | overtimeRequestId 不能为空 |
| overtimeRequestIds 格式错误 | overtimeRequestIds 格式错误 |
| 超过 100 条 | 单次最多允许操作 100 条 |
| 加班单不存在 | 加班草稿不存在 |
| 不是本人单据 | 无权删除该加班草稿 |
| 非 未提交/已退回 状态 | 只允许删除未提交或已退回的加班单 |
| 主表影响行数与 ID 数量不一致 | 删除加班草稿失败 |

### 业务规则

1. 只允许删除 `未提交` 或 `已退回` 状态的单据。
2. 删除为逻辑删除，置 `is_deleted = 1`。
3. 同时逻辑删除关联的明细记录和附件关联记录。
4. 已退回单据删除时，自动禁用旧审批绑定（`approval_biz_rel.is_current` 置为 0）。
5. 批量操作时，任意一条校验失败则整体回滚，所有记录均不删除。
6. ID 自动去重，最多允许 100 条。

### 返回示例

```json

  "data": {
    "successCount": 1,
    "overtimeRequestIds": [1001],

  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

批量删除：

```json
{
  "success": true,
  "data": {
    "successCount": 3,
    "overtimeRequestIds": [1001, 1002, 1003],
    "deleted": true,
    "overtimeRequestId": 1001,
    "requestNo": "OT20260529103651204002"

  "total": null,
```

## 12. 【我要加班】废弃加班单

`POST /api/overtime/request/self/abandon`

### 作用

当前员工撤回自己的审批中加班单。本接口员工端废弃语义为撤回审批：只有审批中且无人处理过的单据可撤回，撤回后单据状态回到未提交，方便重新编辑提交。支持批量操作。

### 权限规则

- 不加 `@ScopeAuthRequired`，仅需 token 校验。
- 只能撤回当前登录员工自己的加班单。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `overtimeRequestId` | Long | 否 | 加班单业务 ID，兼容单条 |
| `overtimeRequestIds` | String | 否 | 加班单业务 ID，批量，逗号分隔，优先使用 |
| `remark` | String | 否 | 撤回原因 |

两个 ID 参数至少传一个。`overtimeRequestIds` 优先级高于 `overtimeRequestId`。

### 返回字段

`ReturnInfo<OvertimeRequestSelfAbandonResultVO>`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `successCount` | Integer | 成功撤回数量 |
| `overtimeRequestIds` | List\<Long\> | 成功撤回的加班单 ID 列表 |
| `abandoned` | Boolean | 是否撤回成功 |
| `overtimeRequestId` | Long | 兼容：第一条加班单 ID |
| `requestNo` | String | 兼容：第一条加班单号 |

### 撤回允许状态

| 状态 | 是否允许 | 说明 |
| ---- | -------- | ---- |
| 未提交 | 不允许 | 请使用删除草稿功能 |
| 审批中 | 允许 | 但必须无人同意/退回过，撤回后回到未提交 |
| 已退回 | 不允许 | 直接编辑后重新提交 |
| 已通过 | 不允许 | 已通过加班单不允许撤回 |
| 已废弃 | 不允许 | 不可重复操作 |

### 校验规则

| 校验 | 错误信息 |
| ---- | -------- |
| overtimeRequestId 和 overtimeRequestIds 都为空 | overtimeRequestId 不能为空 |
| overtimeRequestIds 格式错误 | overtimeRequestIds 格式错误 |
| 超过 100 条 | 单次最多允许操作 100 条 |
| 加班单不存在 | 加班单不存在 |
| 不是本人单据 | 无权废弃该加班单 |
| 未提交状态 | 未提交草稿请使用删除功能 |
| 已退回状态 | 已退回加班单请编辑后重新提交 |
| 已通过状态 | 已通过加班单不允许撤回 |
| 已废弃状态 | 加班单已废弃，不可重复操作 |
| 审批中但缺少审批实例 | 审批中加班单缺少审批实例，无法撤回 |
| 审批中但已有人处理 | 审批流程已有人处理，无法撤回 |

### 业务规则

1. 只有审批中且审批实例中无人同意/退回过的单据允许撤回。
2. 撤回后审批实例状态置为已撤回，审批任务关闭，审批绑定失效。
3. 撤回后加班单状态回到未提交，员工可重新编辑并提交。
4. 不涉及调休台账回滚（审批中未通过的单据不会生成调休）。
5. 操作人信息从登录上下文获取，不依赖前端传参。
6. 批量操作时，先校验所有记录，任意一条校验失败则整体回滚。
7. ID 自动去重，最多允许 100 条。

### 按钮权限同步

`/self/page` 返回的按钮权限与此撤回规则保持一致：

| 状态 | canEdit | canDelete | canSubmit | canAbandon |
| ---- | ------- | --------- | --------- | ---------- |
| 未提交 | true | true | true | false |
| 审批中 | false | false | false | true（仅 handledActionCount=0） |
| 已退回 | true | false | true | false |
| 已通过 | false | false | false | false |
| 已废弃 | false | false | false | false |

### 返回示例

单条废弃：

```json
  "data": {
    "successCount": 1,
    "overtimeRequestIds": [1001],
    "abandoned": true,
    "overtimeRequestId": 1001,
    "requestNo": "OT20260529103651204002"
  },

  "currPage": null,

  "messageType": 0
```

5. **审批记录表**（有审批日志时显示）：审批人、审批结果、审批时间、审批意见
