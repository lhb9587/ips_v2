## 说明

审批中心不提供通用新建审批接口。审批实例和审批任务由请假、加班、补签、出差等业务单据提交后在后端内部生成。

请假、加班、补签走正常审批流，生成待审批任务。出差单当前按业务规则自动通过，只写入审批中心记录和动作日志，不生成待审批任务。

提交生效不是审批中心独立接口。提交生效属于业务单据提交模式，由单据提交接口传入提交方式后，后端写入审批中心并直接置为审批通过。

所有 `/api/**` 接口仍由全局拦截器校验 `tokenID`。需要审批权限范围的查询和动作接口会加载当前用户权限上下文。

## 1. 审批中心列表分页查询

`POST /api/approval/center/page`

### 作用

查询审批中心列表，支持全部、待审批、我的申请三个页签。

### 权限规则

- 系统管理员可查看全部审批单。
- HR、考勤员、负责人、组长按权限部门范围查看申请人所在部门内的审批单。
- 前端传父部门时，后端展开父部门及全部子部门，再与当前用户部门权限范围取交集。
- 普通员工在全部页签只查看本人申请或本人参与审批的单据。
- 待审批页签只返回当前登录用户作为待审批审核人的任务。
- 我的申请页签只返回当前登录用户本人申请的单据。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `tab` | String | 是 | 页签：`all` 全部、`pending` 待审批、`mine` 我的申请 |
| `bizType` | String | 否 | 业务类型：`leave` 请假、`overtime` 加班、`supplement` 补签、`trip` 出差 |
| `status` | String | 否 | 审批实例状态：`审批中`、`已通过`、`已退回` |
| `applicantCode` | String | 否 | 申请人员工编码 |
| `applicantName` | String | 否 | 申请人姓名模糊查询 |
| `deptCode` | String | 否 | 申请人部门编码，支持父部门筛选 |
| `startDate` | String | 否 | 提交开始时间 |
| `endDate` | String | 否 | 提交结束时间 |
| `pageNo` | Integer | 否 | 页码，默认 1 |
| `pageSize` | Integer | 否 | 每页条数，默认 10，最大 200 |

### 返回字段

接口返回 `ReturnInfo<List<ApprovalCenterPageItemVO>>`，分页总数放在外层 `total`，当前页放在外层 `currPage`。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `instanceId` | Long | 审批实例ID |
| `taskId` | Long | 当前任务ID，出差自动通过单可能为空 |
| `bizType` | String | 业务类型 |
| `bizTypeName` | String | 业务类型名称 |
| `bizId` | Long | 业务单据ID |
| `bizNo` | String | 业务单据编号 |
| `bizTitle` | String | 业务标题 |
| `applicantCode` | String | 申请人员工编码 |
| `applicantName` | String | 申请人姓名 |
| `deptCode` | String | 申请人部门编码 |
| `deptName` | String | 申请人部门名称 |
| `instanceStatus` | String | 审批实例状态 |
| `currentNodeCode` | String | 当前节点编码 |
| `currentNodeName` | String | 当前节点名称 |
| `taskStatus` | String | 当前任务状态 |
| `receivedTime` | Date | 任务接收时间 |
| `submitTime` | Date | 提交时间 |
| `finishTime` | Date | 完成时间 |
| `canApprove` | Boolean | 当前用户是否可审批通过 |
| `canReject` | Boolean | 当前用户是否可退回 |

## 2. 审批任务详情查询

`POST /api/approval/center/detail`

### 作用

查询审批实例详情、当前任务、审核人列表和动作日志。

### 权限规则

- 系统管理员可查看全部。

- 当前待审批审核人可查看自己待处理的审批单。
- HR、考勤员、负责人、组长可查看申请人在自己权限部门范围内的审批单。

## 3. 审批通过

`POST /api/approval/task/approve`

### 作用

当前审核人审批通过当前待处理任务。当前阶段为或签：任一待审批审核人通过后，任务通过，其他待审批审核人跳过，审批实例置为已通过，并回写业务单据状态。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `taskId` | Long | 是 | 审批任务ID |
| `operatorTalentCode` | String | 否 | 操作人员工编码 |
| `operatorName` | String | 否 | 操作人姓名 |
| `opinion` | String | 否 | 审批意见 |

`operatorUserId` 由后端从 token 登录用户覆盖，前端传值不作为审批身份依据。

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `instanceId` | Long | 审批实例ID |
| `taskId` | Long | 审批任务ID |
| `bizType` | String | 业务类型 |
| `bizId` | Long | 业务单据ID |
| `actionType` | String | 动作类型 |
| `instanceStatus` | String | 审批实例状态 |
| `taskStatus` | String | 审批任务状态 |
| `operatorUserId` | Integer | 操作人用户ID |
| `operatorName` | String | 操作人姓名 |
| `operateTime` | Date | 操作时间 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "instanceId": 10001,
    "taskId": 20001,
    "bizType": "leave",
    "bizId": 30001,
    "actionType": "同意",
    "instanceStatus": "已通过",
    "taskStatus": "已通过",
    "operatorUserId": 3312,
    "operatorName": "李四",
    "operateTime": "2026-05-25 10:30:00"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

## 6. 审批委托设置

`POST /api/approval/center/delegate/create`

### 作用

当前登录用户设置审批委托，将本人所有待审批任务转交给被委托人。设置后，已有的待审批任务立即转移，后续新任务也会自动转交。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `toUserId` | Integer | 是 | 被委托人用户ID |
| `remark` | String | 否 | 备注 |

`fromUserId`、`operatorUserId`、`operatorName` 由后端从 token 登录用户覆盖，前端不需要传。

### 返回字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `ruleId` | Long | 委托规则ID |
| `fromUserId` | Integer | 委托人用户ID |
| `toUserId` | Integer | 被委托人用户ID |
| `affectedTaskCount` | Integer | 本次立即转交的待审批任务数量 |
| `effectiveTime` | Date | 生效时间 |

### 返回示例

```json
{
  "success": true,
  "data": {
    "ruleId": 50001,
    "fromUserId": 3312,
    "toUserId": 3267,
    "affectedTaskCount": 3,
    "effectiveTime": "2026-05-25 11:10:00"
  },
  "total": null,
  "currPage": null,
  "message": "ok",
  "messageType": 0
}
```

## 8. 调整审核人

## 9. 调整审核人记录查询

`POST /api/approval/center/assignee/adjust-record`

### 作用

查询某个审批任务的审核人调整记录，查看"谁在什么时候把审核人从谁调整成谁"。

### 权限规则

- 系统管理员可查。
- 申请人本人可查。
- 当前任务审核人可查（任意状态）。
- 有部门范围的角色（HR、考勤员、负责人、组长）可查申请人在自己权限部门范围内的审批单。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `taskId` | Long | 是 | 审批任务ID |
| `pageNo` | Integer | 否 | 页码，默认 1 |
| `pageSize` | Integer | 否 | 每页条数，默认 10，最大 200 |

### 返回字段

接口返回 `ReturnInfo<List<ApprovalAssigneeAdjustRecordItemVO>>`，分页总数放在外层 `total`，当前页放在外层 `currPage`。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `actionId` | Long | 动作日志ID |
| `taskId` | Long | 审批任务ID |
| `instanceId` | Long | 审批实例ID |
| `operatorUserId` | Integer | 操作人用户ID |
| `operatorName` | String | 操作人姓名 |
| `adjustTime` | Date | 调整时间 |
| `reason` | String | 调整原因 |
