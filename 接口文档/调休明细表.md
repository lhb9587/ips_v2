# 调休明细表接口

基础路径：`/api/leave/comp-off/detail`

统一返回结构：`ReturnInfo<T>`

公共规则：

| 规则 | 说明 |
|---|---|
| 请求方式 | 全部使用 `POST` |
| 参数方式 | 表单传参，不使用 `@RequestBody` |
| token | `tokenID` 通过 query 参数或请求头传入 |
| 分页返回 | `data` 直接返回列表，`total` 返回总数，`currPage` 返回当前页 |
| 权限范围 | 查询接口标注 `@ScopeAuthRequired` |
| 部门筛选 | 传入父部门时，按 `UserAuthContext.deptScopeTree` 展开子部门，再与当前用户 `deptScopes` 取交集 |

## 1. 调休明细分页查询

`POST /api/leave/comp-off/detail/page`

### 作用

逐条展示员工调休生成台账，每行对应一条 `change_type='生成'` 的记录，附带该批次（lot）的汇总使用/失效/余额。

### 请求参数

| 字段 | 必填 | 说明 |
|---|---|---|
| deptCode | 否 | 组织编码，支持父部门展开 |
| talentCode | 否 | 员工编码模糊查询 |
| talentName | 否 | 员工姓名模糊查询 |
| leavePolicyCode | 否 | 假期制度编码 |
| baseYear | 否 | 月份序号基准年，不传默认当前年 |
| periodStartMonth | 否 | 开始月份序号，不传默认 `1` |
| periodEndMonth | 否 | 结束月份序号，不传默认 `24` |
| pageNo | 否 | 页码，默认 `1` |
| pageSize | 否 | 每页条数，默认 `20`，最大 `200` |

### 月份序号规则

1. `periodStartMonth` 和 `periodEndMonth` 对应页面的"第 1 到 24 月"。
2. `baseYear` 的 1 月是第 `1` 月。
3. `baseYear + 1` 的 12 月是第 `24` 月。
4. 例如 `baseYear=2026&periodStartMonth=1&periodEndMonth=24`，实际查询范围是 `2026-01-01` 到 `2027-12-31`。
5. `periodStartMonth` 必须大于等于 `1`。
6. `periodEndMonth` 必须小于等于 `24`。
7. `periodEndMonth` 不能小于 `periodStartMonth`。

### 返回字段

| 字段 | 说明 |
|---|---|
| talentCode | 员工编码 |
| talentName | 员工姓名 |
| deptCode | 组织编码 |
| deptName | 组织名称 |
| id | 台账主键 |
| otType | OT 类型：OT1 / OT2 / OT3 |
| changeHours | 本次生成小时数 |
| lotUsedHours | 同 lot 批次已使用小时 |
| lotExpiredHours | 同 lot 批次已失效小时 |
| lotRemainHours | 同 lot 批次剩余小时 |
| occurTime | 生成时间 |
| expireTime | 失效截止时间 |
| bizNo | 业务单号 |

### 处理规则

1. 每行对应 `attendance_comp_off_ledger` 中一条 `change_type='生成'` 的记录。
2. `lotUsedHours`、`lotExpiredHours`、`lotRemainHours` 为同 `lot_id` 下所有流水的汇总值。
3. 冲销会抵消已用：`lot.used_hours = SUM(使用) - SUM(冲销)`。
4. `otType` 读取 `attendance_comp_off_ledger.ot_type`，取值为 `OT1/OT2/OT3`。
5. 调休有效期按生成记录的 `expire_time` 判断，业务口径为生成后 `3个月` 失效。
6. 普通员工不允许查询全员调休明细。
7. 系统管理员、HR、考勤员、部门负责人允许查询。
8. 非系统管理员必须按当前用户部门权限范围过滤。
