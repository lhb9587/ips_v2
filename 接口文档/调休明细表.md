基础路径：`/api/leave/comp-off/detail`

统一返回结构：`ReturnInfo<T>`

公共规则：

| 规则 | 说明 |
|---|---|
| 请求方式 | 全部使用 `POST` |
| 参数方式 | 表单传参，不使用 `@RequestBody` |
| token | `tokenID` 通过 query 参数或请求头传入 |
| 分页返回 | `data` 直接返回列表，`total` 返回总数，`currPage` 返回当前页 |

## 1. 调休明细分页查询

`POST /api/leave/comp-off/detail/page`

### 作用

查询员工调休额度生成、使用、失效和剩余情况，按员工和调休生成周期汇总展示，并按 `OT1/OT2/OT3` 分维度返回。

### 请求参数

| 字段 | 必填 | 说明 |
|---|---|---|
| deptCode | 否 | 组织编码，支持父部门展开 |
| talentCode | 否 | 员工编码模糊查询 |
| talentName | 否 | 员工姓名模糊查询 |
| leavePolicyCode | 否 | 假期制度编码 |
| baseYear | 否 | 月份序号基准年，不传默认当前年 |
| periodStartMonth | 否 | 开始月份序号，不传默认 `1` |
| periodEndMonth | 否 | 结束月份序号，不传默认 `24` |
| pageNo | 否 | 页码，默认 `1` |
| pageSize | 否 | 每页条数，默认 `20`，最大 `200` |

### 月份序号规则

1. `periodStartMonth` 和 `periodEndMonth` 对应页面的“第 1 到 24 月”。
2. `baseYear` 的 1 月是第 `1` 月。
3. `baseYear + 1` 的 12 月是第 `24` 月。
4. 例如 `baseYear=2026&periodStartMonth=1&periodEndMonth=24`，实际查询范围是 `2026-01-01` 到 `2027-12-31`。
5. `periodStartMonth` 必须大于等于 `1`。
6. `periodEndMonth` 必须小于等于 `24`。
7. `periodEndMonth` 不能小于 `periodStartMonth`。

### 返回字段

| 字段 | 说明 |
|---|---|
| talentCode | 员工编码 |
| talentName | 员工姓名 |
| deptCode | 组织编码 |
| deptName | 组织名称 |
| periodName | 周期，按调休生成月份返回，例如 `2026年05月` |
| quotaHours | 调休生成总额度 |
| quotaOt1Hours | OT1 生成额度 |
| quotaOt2Hours | OT2 生成额度 |
| quotaOt3Hours | OT3 生成额度 |
| usedHours | 已调休总额度 |
| usedOt1Hours | OT1 已调休额度 |
| usedOt2Hours | OT2 已调休额度 |
| usedOt3Hours | OT3 已调休额度 |
| remainHours | 剩余总额度 |
| remainOt1Hours | OT1 剩余额度 |
| remainOt2Hours | OT2 剩余额度 |
| remainOt3Hours | OT3 剩余额度 |
| expiredHours | 已失效总额度 |
| expiredOt1Hours | OT1 已失效额度 |
| expiredOt2Hours | OT2 已失效额度 |
| expiredOt3Hours | OT3 已失效额度 |

### 处理规则

1. 调休额度来源于 `attendance_comp_off_ledger`。
2. `change_type = 生成` 代表调休生成额度。
3. `change_type = 使用` 代表调休使用额度。
4. `change_type = 失效` 代表调休失效额度。
5. 调休生成按 `1:1` 口径落台账，本接口只查询已落表结果，不现场重新计算。
6. 调休有效期按生成记录的 `expire_time` 判断，业务口径为生成后 `3个月` 失效。
7. OT 维度读取 `attendance_comp_off_ledger.ot_type`，取值为 `OT1/OT2/OT3`。
8. 剩余额度按同一 `lot_id` 下所有流水的 `change_hours` 汇总得到。
9. 普通员工不允许查询全员调休明细。
10. 系统管理员、HR、考勤员、部门负责人允许查询。
11. 非系统管理员必须按当前用户部门权限范围过滤。
