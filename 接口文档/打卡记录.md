## 1. 打卡记录分页查询

后台查询打卡记录列表，只读接口，不写库。按当前用户权限范围过滤，支持组织、姓名、日期范围分页筛选。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/attendance/punch/record/page` |
| Content-Type | `application/x-www-form-urlencoded` |
| 鉴权要求 | 需要登录（tokenID） + 数据权限范围（@ScopeAuthRequired） |
| Controller | `AttendancePunchRecordController` |
| Service | `AttendancePunchRecordPageService` |
| 数据源 | `@DS("whd")` |

### 权限规则

| 角色 | 数据范围 |
|------|----------|
| 系统管理员 | 查询全部（不传 deptCode 时不做部门过滤） |
| HR / 考勤员 / 部门负责人 | 按当前用户 `deptScopes` 过滤；前端传 `deptCode` 时展开子部门后与权限取交集 |
| 普通员工 | 不开放，直接返回无权限异常 |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tokenID` | String | 是 | 统一鉴权令牌 |
| `deptCode` | String | 否 | 组织编码；为空查当前用户权限范围内全部部门；不为空时展开子部门后与权限取交集 |
| `talentName` | String | 否 | 员工姓名，模糊查询 |
| `startDate` | String | 否 | 开始日期，格式 `yyyy-MM-dd`，默认当前月第一天 |
| `endDate` | String | 否 | 结束日期，格式 `yyyy-MM-dd`，默认当前月最后一天 |
| `pageNo` | Integer | 否 | 页码，默认 `1` |
| `pageSize` | Integer | 否 | 每页条数，默认 `10`，最大 `200` |

### 部门树规则

1. 从 `ctx.getDeptScopes()` 获取当前用户可见部门
2. 从 `ctx.getDeptScopeTree()` 获取部门树
3. 前端传了 `deptCode` → 先展开为自身+全部子部门
4. 展开结果与 `ctx.getDeptScopes()` 取交集
5. 交集为空 → 直接返回空列表
6. 不传 `deptCode` → 使用当前用户全部 `deptScopes`（不能查全公司）

示例：用户权限范围 `[134, 13401, 13402, 13403]`，前端传 `deptCode=134` → 实际查询 `[134, 13401, 13402, 13403]`

### 日期规则

- `startDate` 为空默认当前月第一天
- `endDate` 为空默认当前月最后一天
- `endDate < startDate` 直接抛异常：`结束日期不能小于开始日期`
- 查询范围：`punch_time >= startDate 00:00:00` 且 `punch_time <= endDate 23:59:59`

### 响应体

#### 成功响应

```json
{
  "success": true,
  "data": [
    {
      "recordId": 1001,
      "talentCode": "30028",
      "talentName": "张三",
      "deptCode": "100",
      "deptName": "万慧达/知识产权/商标部",
      "attendanceNo": "KQ001",
      "punchDate": "2026-05-10",
      "punchTime": "2026-05-10 08:55:32",
      "sourceType": "设备打卡",
      "punchLocation": "前台考勤机",
      "remark": null,
      "status": "正常"
    }
  ],
  "total": 45,
  "currPage": 1,
  "message": "ok",
  "messageType": 0
}
```

#### 返回字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `recordId` | Long | 打卡记录 ID |
| `talentCode` | String | 员工编码 |
| `talentName` | String | 员工姓名（来自 `ip_db.talent_person`） |
| `deptCode` | String | 组织编码（来自 `ip_db.talent_person.deptCode`） |
| `deptName` | String | 组织名称（来自 `ip_db.talent_organization.kingDeeFullGroupName`） |
| `attendanceNo` | String | 考勤编号 |
| `punchDate` | String | 打卡日期，格式 `yyyy-MM-dd` |
| `punchTime` | String | 打卡时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `sourceType` | String | 打卡来源（设备打卡、手工导入等） |
| `punchLocation` | String | 打卡地点 |
| `remark` | String | 描述 |
| `status` | String | 状态 |

#### 失败响应

**无权限（普通员工）：**
```json
{
  "success": false,
  "data": null,
  "total": null,
  "currPage": null,
  "message": "当前用户无权查看打卡记录",
  "messageType": 20004
}
```

**日期错误：**
```json
{
  "success": false,
  "data": null,
  "total": null,
  "currPage": null,
  "message": "结束日期不能小于开始日期",
  "messageType": 10001
}
```

### 排序规则

默认排序：`punch_time DESC` → `record_id DESC`

### 调用示例

```bash

  -d "tokenID=177691146506299921" \
  -d "deptCode=134" \
  -d "startDate=2026-05-01" \
  -d "endDate=2026-05-31" \
  -d "pageNo=1" \
  -d "pageSize=10"
```

## 2. 打卡记录导入模板下载

复制打卡记录导入 Excel 模板文件到导出目录，返回文件路径供前端下载。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/attendance/punch/record/import-template` |
| 鉴权要求 | 需要登录（tokenID），不需要数据权限范围 |
| 返回类型 | `ReturnInfo<ExportFileVO>` |
| Service | `AttendancePunchRecordTemplateService` |

### 请求参数

无额外参数，只需 tokenID。

### 模板字段

| 列 | 字段名 | 必填 | 说明 |
|----|--------|------|------|
| A | attendanceNo | 条件必填 | 考勤编号，与 talentCode 至少填一个 |
| B | talentCode | 条件必填 | 员工编码，与 attendanceNo 至少填一个 |
| C | talentName | 否 | 员工姓名（仅展示用，不参与匹配） |
| D | punchDate | 是 | 打卡日期 |
| E | punchTime | 是 | 打卡时间 |
| F | sourceType | 否 | 打卡来源 |
| G | punchLocation | 否 | 打卡地点 |
| H | remark | 否 | 备注 |

### 成功响应

```json
{
  "success": true,
  "data": {
    "filePath": "/template/ip_attendance/punch_record_import_template/2026-05-20/1778234507579/打卡记录导入模板_1778234507579.xlsx",
    "fileName": "打卡记录导入模板_1778234507579.xlsx"
  },
  "message": "ok",
  "messageType": 0
}
```

### 失败响应

**模板文件不存在：**
```json
{
  "success": false,
  "data": null,
  "total": null,
  "currPage": null,
  "message": "打卡记录导入模板不存在",
  "messageType": 50000
}
```

**文件复制失败：**
```json
{
  "success": false,
  "data": null,
  "total": null,
  "currPage": null,
  "message": "打卡记录导入模板复制失败",
  "messageType": 50000
}
```

### 调用示例

```bash
curl -X POST "http://localhost:9091/api/attendance/punch/record/import-template" \
  -d "tokenID=177691146506299921"
```

## 3. 打卡记录 Excel 导入

上传 Excel 文件，自动识别模板类型（中文模板 / 考勤机导出模板），逐行校验并批量导入打卡记录。

### 基本信息

| 项目 | 说明 |
|------|------|
| 请求路径 | `POST /api/attendance/punch/record/import` |
| Content-Type | `multipart/form-data` |
| 鉴权要求 | 需要登录（tokenID），仅系统管理员和考勤员可导入 |
| Controller | `AttendancePunchRecordController` |
| Service | `AttendancePunchRecordImportService` |
| 数据源 | `@DS("whd")` |

### 权限规则

| 角色 | 是否允许 |
|------|----------|
| 系统管理员 | 允许，不限部门范围 |
| 考勤员 | 允许，仅能导入自己部门权限范围内的考勤编号 |
| HR / 部门负责人 | 不允许 |
| 普通员工 | 不允许 |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tokenID` | String | 是 | 统一鉴权令牌 |
| `file` | MultipartFile | 是 | Excel 文件（.xlsx） |

### 支持模板类型

#### 中文模板（cn_template_v1）

| 列 | 表头名 | 必填 | 映射字段 |
|----|--------|------|----------|
| A | 考勤编号 | 是 | attendanceNo |
| B | 员工编码 | 否 | talentCode |
| C | 员工姓名 | 否 | talentName |
| D | 打卡日期 | 是 | punchDate（yyyy-MM-dd） |
| E | 打卡时间 | 是 | punchTime（HH:mm:ss） |
| F | 打卡来源 | 否 | sourceType |
| G | 打卡地点 | 否 | punchLocation |
| H | 备注 | 否 | remark |

#### 考勤机导出模板（machine_template_v1）

| 列 | 表头名 | 必填 | 映射字段 |
|----|--------|------|----------|
| - | f_workno | 是 | attendanceNo |
| - | att_date | 是 | punchDate |
| - | punchtime | 是 | punchTime（可能含完整日期时间 yyyy-MM-dd HH:mm:ss） |
| - | f_cardno | 否 | attendanceNo2（备用考勤编号） |
| - | name | 否 | talentName |

### 模板自动识别

- 系统扫描第一行表头，匹配中文模板或考勤机模板的关键列名
- 必须匹配到 `attendanceNo`、`punchDate`、`punchTime` 三个必填字段才算识别成功
- 无法识别时返回错误：`无法识别Excel模板类型，请使用标准模板`

### 逐行校验规则

| 序号 | 校验项 | 失败提示 |
|------|--------|----------|
| 1 | 考勤编号不能为空 | `考勤编号不能为空` |
| 2 | 打卡日期不能为空 | `打卡日期不能为空` |
| 3 | 打卡时间不能为空 | `打卡时间不能为空` |
| 4 | 日期/时间格式正确 | `打卡日期或时间格式错误，日期要求yyyy-MM-dd，时间要求HH:mm:ss` |
| 5 | 考勤编号对应档案存在 | `考勤编号[xxx]未找到有效考勤档案` |
| 6 | 部门权限范围（非系统管理员） | `考勤编号[xxx]所属部门不在当前用户权限范围内` |
| 7 | 数据库重复打卡检查 | `该员工在yyyy-MM-dd HH:mm:ss已有打卡记录`（跳过，不计入失败） |
| 8 | 导入批次内去重 | `本次导入中存在重复的打卡记录`（跳过，不计入失败） |

### 导入记录字段

成功导入的打卡记录固定字段：

| 字段 | 值 |
|------|-----|
| source_type | `import` |
| source_biz_type | `punch_record_import` |
| source_biz_id | 批次ID（batchId） |
| batch_id | 批次ID |
| status | `正常` |
| talent_code | 来自考勤档案 |
| dept_code | 来自考勤档案（attendanceOrgCode） |
| record_id | `System.currentTimeMillis() * 10000 + 自增序列` |

### 导入状态

| 状态值 | 条件 |
|--------|------|
| `success` | 全部成功（failCount = 0） |
| `partial_success` | 部分成功（successCount > 0 且 failCount > 0） |
| `failed` | 全部失败（successCount = 0，跳过不计入失败） |

> **注意**：重复打卡记录（数据库已有 + 批次内重复）会被**跳过**，不计入 `failCount`，不影响 `importStatus`。跳过记录在 `skipCount` 和 `skipRows` 中体现。

```json

  "data": {
```
