# API 与请求封装

## 基本规则

- 请求统一走 `@/utils/request`。
- API 函数放在 `src/api/<业务模块>.js`。
- URL 常量放在对应 `*.config.js`。
- 不在页面或组件里直接写 `axios`、`fetch` 或裸 URL。
- 不造后端字段、状态码、错误码或业务枚举。

## API 文件写法

- 优先模仿同业务模块已有 API 文件的导出方式、命名和参数处理。
- 列表、详情、新增、编辑、删除、导入、导出分别使用既有项目惯例命名。
- 上传、下载、取消请求等特殊逻辑先找项目已有实现。
- 需要新增字段时，以接口文档或后端确认为准。

## 页面调用

- 页面只调用 API 层封装，不拼 URL。
- loading、空数据、异常提示沿用同类型页面写法。
- 分页参数、筛选参数、排序参数按后端约定透传或转换。
- 接口失败、超时、空数据要覆盖基础状态。

## 联调排查

1. 先确认环境变量、base URL 和 `vue.config.js` proxy。
2. 再检查接口路径是否重复拼接 `/v2` 或业务前缀。
3. 确认请求方法、content type、参数位置和返回结构。
4. 导入导出类接口额外确认 blob、文件名和错误返回处理。
